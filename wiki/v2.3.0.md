# v2.3.0

A minor release with one addition: `position` gains `$logical`. No member is
added or removed, and no existing call changes its output.

Signatures and argument details come from `gerillass.json`. What is written out
below is the part that is not in there.

| Member | Kind | What changed for a page |
|---|---|---|
| `position` | mixin | signature: `$logical`, false by default, for offsets that follow the writing direction |

---

## Work in `gerillass.com`

### The playground

No member was added, so the member menu needs nothing. Two things wait for npm,
and must not be done before it:

- **`FALLBACK`** in `site/src/components/Playground/versions.js`: add `2.3.0`
  and make it `latest`.
- **`demos.json`**: run `npm run playground-demos --prefix site`. It changes the
  `position` demo to the new `$logical` example, because that is now the fullest
  one on the page. The playground compiles against the published version, and
  2.2.1 refuses `$logical`, so regenerating early breaks that demo. Checked
  while preparing this release: `position` was the only demo that changed.

Since 2.2.1 the playground also shows the library's `@warn` messages above the
CSS. That is a site change, already deployed, and needs nothing for this
release.

### The rest of the site

The header badge and both download buttons follow `package.json`; deploy after
the `v2.3.0` tag is pushed, or the download link is a 404. Leave the
announcement banner.

## Work in `docs.gerillass.com`

Every example on the documentation pages was compiled against 2.2.1 and 2.3.0.
The only difference is the new `$logical` example on `position`, which 2.2.1
refused because the argument did not exist. The page is **already updated in
this release**: the argument and a left-to-right and right-to-left example.

## Where the measurement is

`todos/fix-plan.md`, under A3, in Chrome 152: under `dir="ltr"`
`inset-block-start` and `inset-inline-start` put a box where `top` and `left`
did, for one offset and for four, and under `dir="rtl"` where the mirrored
physical offsets did, while a physical `left: 16px` stayed 16px from the left in
both. On the documentation page the example's badge sits 12px from the left in
the left-to-right box and 12px from the right in the right-to-left one.

The item was added for consistency with `triangle` and `border-radius` rather
than for saved typing, which the entry records: for one offset, `inset-*` by
hand is as short.
