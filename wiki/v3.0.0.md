# v3.0.0

A major release. The two gradient mixins are replaced by one, and
`text-gradient` takes its arguments in a new order. `MIGRATION.md` has every
old call's new form.

Signatures and argument details come from `gerillass.json`. What is written out
below is the part that is not in there.

| Member | Kind | What changed for a page |
|---|---|---|
| `gradient` | mixin | **added**: linear, radial and conic gradients, plain or repeating, with `$in` for a colour space |
| `gradientValue` | function | **added**: the same gradient as a value, for layering, `mask-image` and `border-image` |
| `linear-gradient` | mixin | **removed**, replaced by `gradient` |
| `radial-gradient` | mixin | **removed**, replaced by `gradient` |
| `text-gradient` | mixin | signature: colours first, then every argument `gradient` takes |

`background-image`, `background-dots` and `background-stripes` build their
gradients through the same code as `gradient` now, with byte-identical output
for every call that compiled before. `background-image`'s `$filter-direction`
also accepts any angle unit, `"to top"` and `var()`.

## Work in `gerillass.com`

### The playground

Two things wait for npm, and must not be done before it:

- **`FALLBACK`** in `site/src/components/Playground/versions.js`: add `3.0.0`
  and make it `latest`.
- **`demos.json`**: run `npm run playground-demos --prefix site`. It adds a
  `gradient` demo, drops `linear-gradient` and `radial-gradient`, and changes
  the `text-gradient` demo to the new argument order. The playground compiles
  against the published version, and 2.3.1 has no `gradient` and takes
  `text-gradient`'s direction first, so regenerating early breaks both demos.

The member menu reads the published source, so it gains `gradient` and loses
the two old mixins by itself once 3.0.0 is on npm.

The home page's parked live playground section plays a `text-gradient` demo
from `demos.json` and compiles it against the working tree while the site
builds. It is commented out, so nothing runs today; if it comes back before the
demos are regenerated, that demo fails the build.

### The announcement band

Rewritten for this release, as every major release now does: 3.0.0, that the
gradient mixins changed, and a link to `MIGRATION.md`.

### The rest of the site

The header badge and both download buttons follow `package.json`; deploy after
the `v3.0.0` tag is pushed, or the download link is a 404.

The documentation lives in this repository under `site/content/docs`, and the
pages are **already updated in this release**:

- `gradient.mdx`: new, 30 examples. It includes every example the two removed
  pages had, rewritten for `gradient`, then conic, repeating and interface

  `/docs/radial-gradient` to it.
- `gradient-value.mdx`: new, four examples and what it refuses.
- `text-gradient.mdx`: the new argument order, the old examples rewritten, and
  oklab, conic, repeating and six interface examples.

`WITHOUT_DOCS_PAGE` in `tools/build-llms-txt.js` and run `npm run manifest`, so
`llms.txt` links to the pages rather than the source.

## Where the measurements are

`todos/gradient.md` has all of it. In short:

- **The old mixins' output.** The 22 calls in their documentation, manifest
  and specs were compiled against them and rewritten for `gradient`: every
  gradient value matched. Only the property changed, `background` to
  `background-image`.
- **Why that property.** In Chrome 152, Firefox 156 and Safari 26.6.2, the
  shorthand reset a `background-color` and `background-size` set before it to
  `transparent` and `auto`; `background-image` left them alone.
- **What the builder accepts and refuses.** 78 declarations, computed in all
  three browsers, which agreed on every one: each accepted form kept, each
  refused form dropped. That covers every direction form, 20 colour spaces and
  `in var()`, and the conic trap: a conic stop takes an angle or a percentage,
  and `conic-gradient(red 10px, blue)` is dropped.
- **What `$in` changes.** Blue to yellow in the default sRGB goes grey in the
  middle; `in oklab` stays clear; `in oklch` shows a visible step near green,
  where colours leave the sRGB gamut, seen in Chrome.
- **The fallback.** A declaration a browser cannot parse is dropped and an
  earlier one stays, simulated in Chrome with an unknown space name. Not tested
  in a browser older than Chrome 111.
- **A single colour stop.** Kept only from Chrome 135, Firefox 136 and Safari
  18.4, from the compat data rather than an old browser, which is why it warns.
- **`text-gradient`.** 15 calls in the old order, rewritten in the new, compile
  to identical CSS. On the documentation, word-sized examples are spans:
  a gradient paints the element's box, and a page-wide block spread a diagonal,
  radial or conic gradient far past the word.
