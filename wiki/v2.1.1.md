# v2.1.1

A fix release. No member is added or removed, and no call that produced
working CSS changes its output, apart from a handful that now raise because
their output ignored what the call said. `CHANGELOG.md` lists those.

Signatures and argument details come from `gerillass.json`. What is written out
below is the part that is not in there: what moved, which pages it touches, and
where the measurements are.

Since 2.1.0 both sites live in this repository, under `site/`, so the work below
is in this repository too. The sections keep the old names so a session that
only knows the old layout can still find its way.

| Member | Kind | What changed for a page |
|---|---|---|
| `background-dots` | mixin | signature: `$gutter` defaults to `null`, still five times `$size`; sizes and image accept CSS functions |
| `remove` | mixin | summary: one breakpoint on its own hides at exactly that width |
| `validateLength` | function | summary: `null` is returned quietly |
| `triangle` | mixin | colour takes `currentColor`, `var()`, `color-mix()`, `light-dark()`, `env()`; sizes take CSS functions |
| `background-stripes` | mixin | thickness and image accept CSS functions |
| `background-image`, `brand-logo`, `text-image` | mixins | image accepts `var()`, `url()`, `image-set()`, gradients; direction always checked |
| `after`, `before`, `counter` | mixins | `var()`, `attr()`, `counter()`, `counters()` written as they are |
| `aspect-ratio`, `validateRatio`, `line-clamp` | mixins, function | accept `var()` |
| `breakpoint`, `remove`, `container-query`, `screen-agent` | mixins | refuse `var()` in a condition; `breakpoint` refuses zero or three arguments |
| `position` | mixin | `null` skips an edge without a warning |
| `font-face` | mixin | unknown formats and a `var()` path raise |
| `remify`, `convertToEm`, `clearUnit`, `fontSizer`, `convertToNumber` | functions | refuse input they cannot convert |
| `reset-css` | mixin | no comments in the output |
| `loadify` | mixin | caveat: the call must load the file that calls `init` |

The first three rows are the ones `tools/check-wiki.js` finds, because only
their signature or summary changed in the manifest. The rest changed behaviour
without changing either, which is why this page lists them by hand.

## Work in `docs.gerillass.com`

Every example on the 80 pages was compiled against 2.1.0 and 2.1.1: 274 of 275
give identical CSS, and the one that changed is `reset-css` losing its comments.
So no page shows a wrong output. What had gone stale was prose, in the argument
tables and footnotes, and it is **updated in this release**, on these pages:

| Page | What was out of date |
|---|---|
| `triangle` | `$color` said only "color"; `$size` did not mention CSS functions |
| `background-dots` | `$size`, `$gutter` and `$image` types |
| `background-stripes` | `$thickness` and `$image` types |
| `background-image` | `$image-url` type; a bad `$filter-direction` now raises with one colour |
| `brand-logo` | `$image-url` type |
| `text-image` | the footnote said the URL must be quoted; `var(--x)` is not |
| `after`, `before` | `$content` did not mention `var()`, `attr()` or `counter()` |
| `counter` | the prefix and suffix did not mention CSS functions |
| `aspect-ratio` | "Anything else is refused with an error"; `var()` is now accepted |
| `line-clamp` | `$lines` did not mention `var()` |
| `validate-ratio`, `validate-length` | `var()` and whole numbers; `null` |
| `font-face` | unknown formats and a `var()` path now raise |
| `breakpoint`, `remove`, `container-query`, `screen-agent` | `var()` is refused in a condition |
| `clear-unit` | it takes any number, and refuses anything else |
| `position` | `null` skips an edge |

Each new sentence was checked by compiling the call it describes, 38 of them,
and the site builds. `remove` and `loadify` also gained a warning earlier in the
cycle: `remove` opens on `min` and `max` and explains the single pixel, and
`loadify` explains the module rule with the error it prevents.

## Where the measurements are

`todos/fix-plan.md` records, for each item, the failing case, the fix, whether
existing output changed, and what was measured. The ones a page should be built
on:

- **`var()` in a condition never matches.** Chrome 152:
  `(min-width: var(--wide))` did not apply with `--wide: 200px`, while
  `(min-width: 200px)` did; the same for `min-resolution`. Item F4.
- **`url(var(--x))` loads nothing, `background-image: var(--x)` does**, and
  `content: "var(--label)"` renders the characters. Item F8.
- **`var(--x)/2` in `border-width` is invalid** and falls back to 3px, while
  `calc(var(--x) / 2)` gives the half. Item F9.
- **A CSS-wide keyword inside a `border-color` shorthand is invalid.**
  `CSS.supports` returned false for `transparent transparent inherit`. Item F1.
- **`loadify` fails across modules** unless the calling file loads the one that
  calls `init`, and `init` in the entry file does not help its partials. Item D1.
- **Parcel** fails on a project's own `main` field and on `font-face`'s default
  formats when only `.woff2` exists. Item D3.
