# v2.3.1

A patch release. No member is added or removed. Calls that compiled into CSS a
browser drops, or into a condition that can never match, now stop the build
with a message; `adaptive(0)` and `columnizer(3, 0)` now produce working CSS
instead of broken CSS. This is the whole of `todos/silent-values-plan.md`, S0
to S7, released as one version rather than the four the plan proposed, because
fixes to early steps landed in later commits.

Signatures and argument details come from `gerillass.json`. What is written out
below is the part that is not in there.

| Member | Kind | What changed for a page |
|---|---|---|
| `validateBreakpoint` | function | refuses a word that is not a key in `$map-for-breakpoints`; still returns lengths, percentages, functions, sizing keywords and `null` |

Twenty-seven mixins changed behaviour without a change of signature, so the
manifest check above names only `validateBreakpoint`. The pages for all of them
are listed below.

## Work in `docs.gerillass.com`

These pages were **already updated in this release**, each with the accepted
values in its argument table and a "What it refuses" section whose error
message was copied from a compile:

adaptive, background-dots, background-image, background-stripes, border-radius,
brand-logo, breakpoint, circle, columnizer, container-query, ellipsis, except,
focus-ring, font-face, linear-gradient, only, position, radial-gradient,

Every `scss` example on the documentation pages was compiled against 2.3.0 and
2.3.1: 338 examples, 293 identical. Of the 45 that differ, 42 are the new
"What it refuses" examples, which compiled on 2.3.0 and now raise as the page
says; 1, `only(1, "first")`, already raised on 2.3.0 with a Sass internal error
and now raises with the library's own message; and 2 are image paths holding a
space or a quote, which are now written quoted.

## Where the measurement is

`todos/silent-values-plan.md`, under each of S1 to S7, and its section on the
false-refusal sweep. All of it was taken in Chrome 152. The method, which a
page explaining a refusal can rely on:

- every changed argument was compiled with about 140 kinds of value, including
  `var()`, `env()`, `attr()`, maths functions, CSS-wide keywords, colour
  functions, gradients, `url()`, `paint()`, quoted values, lists, An+B forms and
  values built by interpolation, against the code before and after;
- the CSS of every call that started to raise was split into declarations,
  selectors and conditions, and each was tested in the browser. An error was
  kept only where that CSS was dropped, could never match, or did nothing;
- for S7 the accepted value sets were measured from the mixins' own output
  rather than from each property alone.

Not covered: browsers other than Chrome, and combinations of arguments that are
only wrong together.
