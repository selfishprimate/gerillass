# v2.2.0

A minor release. Three mixins are added, four gain arguments or values, and
three start warning about a form that 3.0.0 will refuse. No call that produced
working CSS changes its output; a few that compiled into CSS a browser drops
now raise, and `CHANGELOG.md` lists them.

Signatures and argument details come from `gerillass.json`. What is written out
below is the part that is not in there: what moved, which pages it touches, and
where the measurements are.

Both sites live in this repository under `site/`, so the work below is here too.

| Member | Kind | What changed for a page |
|---|---|---|
| `focus-ring` | mixin | **new** |
| `motion-safe` | mixin | **new** |
| `tokens` | mixin | **new** |
| `font-face` | mixin | signature: `$font-display`; `var()` in the family, style and weight raises; a quoted style or weight is unquoted |
| `remove` | mixin | summary: one breakpoint on its own prints a warning |
| `breakpoint`, `container-query` | mixins | one argument prints a warning; `container-query` refuses a `$name` a browser drops |
| `triangle` | mixin | logical directions |
| `border-radius` | mixin | logical corners and edges |
| `all-text-inputs` | mixin | `focus-visible` and `user-invalid` |

The first five rows are the ones `tools/check-wiki.js` finds, because their
signature or summary changed in the manifest. The rest changed behaviour
without changing either, which is why this page lists them by hand.

## Work in `gerillass.com`

### The playground

The member menu needs nothing: `site/src/components/Playground/mixins.js` reads
the `@mixin` declarations out of the library source it downloads, so
`focus-ring`, `motion-safe` and `tokens` appear once 2.2.0 is on npm.

Two things wait for npm, and must not be done before it:

- **`FALLBACK`** in `site/src/components/Playground/versions.js`: add `2.2.0`
  to `versions` and make it `latest`.
- **`demos.json`**: run `npm run playground-demos --prefix site`. The playground
  compiles against the published version, and regenerating early breaks it:
  the `all-text-inputs` page's fullest example uses `user-invalid`, which 2.1.1
  refuses. After publishing, it also picks up the three new mixins.

### The rest of the site

The header badge and both download buttons follow `package.json` through
`site/src/release.js`. The download link is a 404 until the `v2.2.0` tag is
pushed, so deploy after the tag. Leave the announcement banner: nothing in this
release breaks a working stylesheet.

## Work in `docs.gerillass.com`

Every example on the documentation pages was compiled against 2.1.1 and 2.2.0.
Eight pages differ, and every difference is a member or an argument that 2.1.1
did not have, or an example written to show a refusal. No example that compiled
in 2.1.1 changed its CSS.

The pages are **already written and updated in this release**:

## Where the measurements are

`todos/fix-plan.md` records each item with its failing case, the change, and
what was measured, all in Chrome 152. The ones a page should be built on:

- **`focus-ring`** (N1): a mouse click on a button or a link does not match
  `:focus-visible` and Tab does; a text input matches on a click too;
  `:focus { outline: none }` leaves a tabbed button with nothing; inside
  `overflow: hidden` a 2px offset leaves only the corners and `-4px` draws the
  ring fully inside. Forced-colors mode was not emulated.
- **`motion-safe`** (N2): both media queries parse; with the block removed, an
  element that fades in from its keyframes stays visible. The reduced-motion
  setting itself was not emulated.
- **`tokens`** (N3): `--x: null` is a value, so `var(--x, red)` never falls
  back; an unquoted `"→"` makes `content: var(--arrow)` compute to `none`; names
  holding `.`, `/`, a space or `#` are dropped. `todos/design-tokens.md` has six
  more measurements for a token layer built on it.
- **Logical directions** (A1, A2): each logical name renders the same borders or
  radii as its physical twin under `dir="ltr"`, and the mirrored twin under
  `dir="rtl"`. Vertical writing modes were not tried.
- **`user-invalid`** (A5): it does not match on load, nor after focusing and
  leaving an empty field; it matches once a field with `abc` in an email input
  is left, and after Submit. Safari and Firefox were not tried.
- **`font-face`** (A4 and its follow-up): `font-display: "swap"` and `var()` in
  `font-display`, `font-family`, `font-style` and `font-weight` are dropped, as
  are a quoted `"italic"` and `"bold"`. A quoted `"var(--f)"` family is kept as
  a name.
- **Container names** (F4, status of the container name): an `@container` rule
  is dropped for `var()`, `none`, `and`, `or`, `default`, the CSS-wide keywords,
  a name with a space or starting with a digit; `not` becomes a negated query.
- **One-argument breakpoints** (B2): nothing new was measured; the single pixel
  is the definition of `(width: 768px)`.
