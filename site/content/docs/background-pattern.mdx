# Background Pattern

<Member name="background-pattern">

The **Background Pattern Sass mixin** draws seventeen patterns with CSS gradients alone: no image file, no SVG, and nothing to download. Fourteen of them tile, from dots and stripes to houndstooth and harlequin, and three light the whole box, which is what the expensive looking marketing pages put behind a hero. Pass the pattern's name, and optionally its colours, its tile and the line inside it.

</Member>

<Hint kind="warning">

**New in Gerillass 4.0.0.** This mixin replaces **Background Dots** and **Background Stripes**, which are both removed. `background-pattern(dots, ...)` and `background-pattern(stripes, ...)` take their place, with the arguments named rather than positional. See the migration guide.

</Hint>

## Arguments

<Arguments of="background-pattern" footnote="The kind is the only positional argument and everything after it is named, as in `background-pattern(grid, $size: 2rem)`. Each pattern reads only the arguments it needs, and passing one it ignores raises rather than doing nothing quietly.">
  <Argument name="$kind" type="string">Which pattern: <code>dots</code>, <code>stripes</code>, <code>grid</code>, <code>checkerboard</code>, <code>crosshatch</code>, <code>zigzag</code>, <code>triangles</code>, <code>brick</code>, <code>waves</code>, <code>houndstooth</code>, <code>gingham</code>, <code>harlequin</code>, <code>sunburst</code>, <code>concentric</code>, <code>glow</code>, <code>vignette</code> or <code>mesh</code>.</Argument>
  <Argument name="$color" type="color, list">One colour, or two or three for the patterns that layer them. The default is <code>currentColor</code> mixed with transparency, so a pattern follows the text colour.</Argument>
  <Argument name="$background" type="color">The colour under the pattern, written as <code>background-color</code>.</Argument>
  <Argument name="$size" type="number">The tile. The default is <code>2rem</code>. A <code>var()</code> or <code>calc()</code> works, and every offset is derived from it. For <code>stripes</code> it is the period, one line plus its gap. For <code>glow</code> and <code>vignette</code> there is no tile: it is how far the light reaches, one value or two, and the default is <code>90% 80%</code>.</Argument>
  <Argument name="$thickness" type="number">The line, dot or mortar inside the tile. The default is a tenth of the tile for <code>dots</code> and an eighth for the rest. For <code>stripes</code> it is the width of each coloured line, and with no <code>$size</code> the period stays twice it.</Argument>
  <Argument name="$angle" type="number">For <code>stripes</code>, <code>crosshatch</code> and <code>zigzag</code>: an angle such as <code>-45deg</code>, or a unitless number read as degrees. For <code>sunburst</code>: how wide one ray is.</Argument>
  <Argument name="$direction" type="string">For <code>triangles</code>: which way they point, <code>up</code>, <code>right</code>, <code>down</code> or <code>left</code>. The default is <code>down</code>. It takes names rather than an angle because only four rotations cut the tile as a triangle at all.</Argument>
  <Argument name="$axis" type="string">For <code>grid</code>: <code>both</code>, <code>block</code> for horizontal lines only, or <code>inline</code> for vertical lines only.</Argument>
  <Argument name="$stagger" type="boolean">For <code>dots</code>, <code>false</code> lines them up in a grid instead of offsetting every other row.</Argument>
  <Argument name="$origin" type="string">Where a pattern drawn from a point starts: the light for <code>glow</code> and <code>vignette</code>, the rays for <code>sunburst</code>, the rings for <code>concentric</code>. A background position, such as <code>50% 100%</code> or <code>top left</code>. The default is the middle, and the bottom edge for <code>glow</code>.</Argument>
  <Argument name="$image" type="string">An image path, laid under the pattern as the last layer. Refused by the patterns that paint every pixel, since it would never be seen.</Argument>
</Arguments>

## Patterns

Each pattern below is its own section, with the colours and the tile changed from one example to the next. The last three, `glow`, `vignette` and `mesh`, are drawn once at the size of the box rather than tiled.

`#0000 0` runs through the compiled CSS and both halves of it are deliberate. `#0000` is transparent written as a four-digit hex, `#rgba` with every channel at zero, and the `0` after it is the stop's position, not a second colour: a stop that comes before the one in front of it is clamped up to it, which is what turns a fade into a hard edge.

### Dots

<Example caption="With no colours the dots are drawn in `currentColor` at low opacity, so they follow the text colour of whatever they sit behind.">
```scss
.hero {
  @include background-pattern(dots, $size: 1.5rem);
}
```
```html
<style>
  .hero { padding: 30px 24px; border-radius: 10px; color: #2f3937; font: 15px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; }
  .hero h2 { margin: 0 0 6px; font-size: 28px; }
  .hero p { margin: 0; color: #657167; }
</style>
<section class="hero">
  <h2>Patterns, not pictures</h2>
  <p>Drawn by the browser, in one line of Sass.</p>
</section>
```
</Example>

<Example caption="`$size` is the tile and `$thickness` the dot, so a big tile with a big dot gives confetti rather than a texture.">
```scss
.confetti {
  @include background-pattern(dots, $color: #5bc0bb #bdc488, $background: #f2f2eb, $size: 34px, $thickness: 5px);
}
```
```html
<style>
  .confetti { height: 150px; border-radius: 10px; }
</style>
<div class="confetti"></div>
```
</Example>

<Hint kind="info">

**Which patterns let an image through.** The image is the last background layer, so it shows wherever the pattern leaves a gap. Two cover every pixel of it and refuse `$image` rather than hiding it: `checkerboard`, and `stripes` with more than one colour. The other sixteen let it through.

</Hint>

<Hint kind="danger">

**A pattern is decoration.** In forced colours mode a browser replaces `background-image` with `none` for everything that is not a `url()`, so every pattern here disappears. Never let one carry meaning, and keep the contrast between text and the colour underneath.

</Hint>

<Hint kind="info">

**What was measured.** Every pattern was drawn in Chrome 152, Firefox 156 and Safari 26.6.2, and all three lay the tiles out the same. One difference: Firefox draws a hard diagonal edge with visible stair steps, where Chrome and Safari smooth it, which shows in `zigzag` and `triangles`. Feathering the colour stop by half a pixel was tried and changed nothing.

</Hint>

## What it refuses

The kind is the only positional argument, and everything after it is named. A
second value in the wrong place stops the build rather than being read as a
colour.

```scss
.element {
  @include background-pattern(dots, 2rem);
}
```
```text
Error: `background-pattern` takes the kind, then named arguments, such as `background-pattern(grid, $size: 2rem)`.
```

A kind it does not draw lists the seventeen it does, so the name is never a
guess.

```scss
.element {
  @include background-pattern(spiral);
}
```
```text
Error: `spiral` is not a pattern `background-pattern` draws. Pass one of: `dots`, `stripes`, `grid`, `checkerboard`, `crosshatch`, `zigzag`, `triangles`, `brick`, `waves`, `houndstooth`, `gingham`, `harlequin`, `sunburst`, `concentric`, `glow`, `vignette`, `mesh`.
```

An argument a pattern does not read raises rather than doing nothing quietly,
and names what that pattern does read. A misspelt argument name is refused the
same way, with the full list.

```scss
.element {
  @include background-pattern(checkerboard, $thickness: 2px);
}
```
```text
Error: `$thickness` does nothing for the `checkerboard` pattern in `background-pattern`. It reads `color`, `size`.
```

An `$image` under a pattern that paints every pixel would never be seen, so it
is refused with the reason rather than drawn into a layer nobody looks at.

```scss
.element {
  @include background-pattern(checkerboard, $image: "/img/a.png");
}
```
```text
Error: `$image` cannot be seen under the `checkerboard` pattern in `background-pattern`: the two colours meet with no gap, so the image would never show. Use a pattern that leaves gaps, or pass one colour.
```

And a stripe as wide as its own period leaves no gap at all, which a browser
paints as a solid colour rather than as stripes.

```scss
.element {
  @include background-pattern(stripes, $size: 4px, $thickness: 10px);
}
```
```text
Error: `10px` is not a valid $thickness for the `stripes` pattern in `background-pattern`: a line as wide as the `4px` period leaves no gap, and a browser paints a solid colour instead of stripes. Pass a $thickness under $size.
```
