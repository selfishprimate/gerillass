# Stretched Link

<Member name="stretched-link">

A card with a link in it is usually meant to be clickable all over, not only on the line of text that carries the link. This mixin stretches that link across its nearest positioned ancestor, so the whole card is the target.

The **Stretched Link** Sass mixin helps you do that. It spreads the clickable area of a link across the entire containing block. 

**Important:** Note that the containing block must have the `position: relative;` style rule, and the mixin must be applied to only one of its children.

<Hint kind="info">

It can be useful with HTML radio buttons or checkbox list design patterns, to control the clickable area of a `<label>` element.

</Hint>

</Member>

## Arguments

<Arguments of="stretched-link" footnote="Sometimes you need to use both the ::before and ::after pseudo-elements of a link. That is why the mixin lets you choose where to apply the stretched link style rules.">
  <Argument name="$value" type="string">Accepts the values <code>before</code> and <code>after</code>. If you do not pass a value, it targets the <code>::before</code> pseudo-element of the selected elements.</Argument>
</Arguments>

## Examples

<Example caption="If no value is passed, the `::before` pseudo-element is targeted by default.">
```scss
.element{
  @include stretched-link;
}
```
</Example>

<Example caption="Pass either the `before` or the `after` option as an argument to choose which pseudo-element you want to target.">
```scss
.element{
  @include stretched-link(after);
}
```
</Example>

<Example caption="Targeting both the `::before` and `::after` pseudo-elements of the selected elements.">
```scss
.element{
  @include stretched-link(before);
  &:after{
    content: "\2192";
  }
}
```
</Example>

<Example caption="Don't forget that the containing block must have the `position: relative;` style rule." listing="<div class=&quot;containing-element&quot;>
&#32;&#32;<a class=&quot;element&quot; href=&quot;https://sample-site.com/&quot;>Stretched Link</a>
</div>">
```scss
.containing-element{
  position: relative;
  .element{
    @include stretched-link(after);
  }
}
```
```html
<style>
  body { background: #f8fafc; font: 14px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #0f172a; }
  .containing-element { position: relative; width: 280px; border-radius: 16px; overflow: hidden; background: #fff; box-shadow: 0 6px 20px rgb(15 23 42 / 0.08); }
  .containing-element img { display: block; width: 100%; height: 130px; object-fit: cover; }
  .body { padding: 14px 16px; }
  .element { color: #0f172a; font-weight: 700; text-decoration: none; }
  .body p { margin: 4px 0 0; color: #64748b; font-size: 13px; }
</style>
<div class="containing-element">
  <img src="/images/landscape.webp" alt="A fjord">
  <div class="body">
    <a class="element" href="#">Lysefjord, Norway</a>
    <p>The whole card is the link, not just this line.</p>
  </div>
</div>
```
</Example>

<Hint kind="warning">

**The card's text cannot be selected with the mouse.** The overlay sits above it, which is the trade every version of this technique makes, Bootstrap's included. If a card's text has to be selectable, leave the link as a link.

</Hint>

<Hint kind="info">

**Changed in Gerillass 4.0.0.** The overlay used to carry `background-color: rgba(0, 0, 0, 0)`, an IE10 fix for a transparent pseudo-element not taking the click, and four separate offsets. It is `inset: 0` now and the colour is gone. Measured in Chrome 152, Firefox 156 and Safari 26.6.2 by asking what a click in the far corner of the card hits: the link, with the old CSS and with the new, in all three. `pointer-events: auto` stays, and it is doing something: with an ancestor at `pointer-events: none` the corner answers the link with it and the body without it.

</Hint>
