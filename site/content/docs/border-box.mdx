# Border Box

<Member name="border-box">

The **Border Box** Sass mixin writes `box-sizing: border-box`, which keeps the
padding and the border inside the width you gave an element rather than adding
them on.

What it writes depends on where it is called. At the root of a stylesheet it is
`*, *::before, *::after`, the reset every project starts with. Inside a
selector it is that element and everything under it, with the descendants in
`:where()` so a `box-sizing` of your own for one of them wins. With `only` it
is that element and its two pseudo-elements, and nothing else.

</Member>

## Arguments

<Arguments of="border-box" footnote="Called at the root with no argument, this is the reset a project writes once and forgets.">
  <Argument name="$value" type="string">Only <code>only</code>, and only inside a selector: it keeps the rule to that element and its <code>::before</code> and <code>::after</code>, where the mixin would otherwise carry on to every descendant. Leave it out for that wider form. Anything else, and <code>only</code> at the root of a stylesheet, is refused.</Argument>
</Arguments>

## Examples

<Example caption="Both boxes ask for `width: 200px`, with 20px of padding and a 4px border, and the dashed line marks where 200px ends. The first is `content-box`, the default: the padding and the border are added outside the width, so 200 + 40 + 8 lands it 48px past the line. The second is the mixin's: the 200px is the whole box, and the content keeps what is left of it, 144px.">
```scss
.element {
  @include border-box;
}
```
```html
<style>
  body { margin: 0; padding: 20px 20px 20px 0; background: #fafaf8; font: 13px/1.45 Inter, ui-sans-serif, system-ui, sans-serif; color: #2f3937; }
  .field { position: relative; padding-left: 20px; }
  .guide { position: absolute; top: 0; bottom: 0; left: 220px; width: 1px; background: repeating-linear-gradient(#db504a 0 6px, #0000 6px 12px); }
  .guide span { position: absolute; top: 0; left: 6px; font-size: 11px; font-weight: 600; color: #db504a; white-space: nowrap; }
  .box { width: 200px; padding: 20px; border: 4px solid #668f80; background: #fff; }
  .box + .box { margin-top: 14px; }
  .box b { display: block; margin-bottom: 2px; }
  .box small { color: #657167; }
  .control { box-sizing: content-box; }
</style>
<div class="field">
  <div class="guide"><span>200px</span></div>
  <div class="box control"><b>content-box</b><small>248px on screen</small></div>
  <div class="box element"><b>border-box</b><small>200px on screen</small></div>
</div>
```
</Example>

<Example caption="`only` keeps it to the element itself and its two pseudo-elements, which is what a component wants when its children have box sizing of their own.">
```scss
.element {
  @include border-box("only");
}
```
</Example>

<Example caption="At the root of a stylesheet it is the universal reset, on every element and every pseudo-element.">
```scss
@include border-box;
```
</Example>

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** Called inside a selector with no argument, the descendants are written inside `:where()`, so a `box-sizing` of your own for one of them wins where it used to lose. At the root of a stylesheet nothing changes.

</Hint>

## What it refuses

`only` limits the rule to the selector it is called in, so at the root of a
stylesheet there is nothing for it to limit.

```scss
@include border-box("only");
```
```text
Error: `only` has no meaning at the root of a stylesheet, because there is no selector to limit the effect to. Call `border-box("only")` inside a selector, or pass no argument at all.
```

And it is the only argument there is, so anything else names both forms.

```scss
.element {
  @include border-box(all);
}
```
```text
Error: `all` is not a valid argument for `border-box`. Pass `"only"` inside a selector to affect just that element, or pass no argument at all.
```
