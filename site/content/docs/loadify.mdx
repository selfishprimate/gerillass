# Loadify

<Member name="loadify">

The **Loadify** Sass mixin fades an element in as the page arrives, and gives a group of them the delay that turns one fade into a sequence.

<Hint kind="info">

**The element is visible by default, and the animation only fades it in.** The keyframes start at `opacity: 0` and `animation-fill-mode: backwards` applies that during the delay, so the fade looks the same as before while an animation that never runs leaves the content where it is. Under `prefers-reduced-motion: reduce` the mixin writes `animation: none`, and nothing else is needed.

</Hint>

</Member>

<KeepScroll />

<Hint kind="info">

**Refreshing keeps your place on this page.** The effect only runs when the page loads, so every example below asks you to refresh. This one page puts the scroll position back where it was, which the rest of the site does not do, so the demo you are looking at is the one that replays.

</Hint>

## Arguments

<Arguments of="loadify" footnote="A time is given in seconds (s) or milliseconds (ms) and the unit is always required. The duration must be zero or positive; the delay may be negative, which starts the fade part of the way in.">
  <Argument name="$mode" type="string">Accepts <code>init</code> at the root of your stylesheet, which writes the keyframes once. Since 4.0.0 a stylesheet that forgets it still builds: the elements simply do not fade.</Argument>
  <Argument name="$delay" type="time">Specifies the amount of time a design element must wait before it starts appearing on the page. The default value is set to <code>0.2s</code>. One time, with its unit, or a <code>var()</code>. A negative delay starts the fade part of the way in rather than waiting: <code>loadify(-0.25s)</code> begins a <code>0.5s</code> fade halfway, at an opacity of 0.80.</Argument>
  <Argument name="$duration" type="time">Sets the length of time a page element takes to load. <strong>This is the second argument. It must always come last and cannot be used on its own.</strong> The default value is <code>0.5s</code>. It cannot be negative: only a delay may be, so a browser reads the pair the other way round and the fade is over before the page paints.</Argument>
</Arguments>

<Hint kind="info">

**Call `loadify(init)` once at the root**, to write the keyframes the elements animate to. Since 4.0.0 it can live in any file: the mixin no longer works by `@extend`, so the call and the initializer no longer have to see each other, and a stylesheet that leaves `init` out builds as before with no fade.

</Hint>

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** The element used to be hidden and revealed by the animation, so anything that stopped the animation -- a later `animation: none`, which a component or a reset writes easily -- left the content invisible for good, and gone from the accessibility tree with it. It is visible now and the animation only fades it in.

</Hint>

<Hint kind="danger">

**A time needs its unit, and there is one time per argument.** Both were accepted until 4.0.0 and both wrote CSS that does nothing: a bare `0` is read as the iteration count in the `animation` shorthand, so the fade never runs, and a second time makes the browser drop the whole declaration. Write `loadify(0s)` and `loadify(0.2s, 0.4s)`, where the first time is the delay and the second the duration. See [what it refuses](#what-it-refuses) below.

</Hint>

<Hint kind="info">

**Inside a selector the mixin writes one `animation` shorthand**: the name, the duration, the delay and `backwards`. With no arguments that is `animation: loadify 0.5s 0.2s backwards`, which is what the example above uses. Because it is the shorthand, an `animation` of your own on the same element replaces it rather than adding to it.

</Hint>

## What it refuses

A bare number is not a time, and the CSS it used to write did nothing at all:
in the `animation` shorthand a unitless value is read as the iteration count,
so `0` stopped the fade from running rather than making it instant.

```scss
.a {
  @include loadify(0);
}
```
```text
Error: `0` is not a valid time: a time needs its unit, and a bare `0` is read as the iteration count in the `animation` shorthand, where it stops the animation from running at all. Write `0s`. Pass a duration in seconds or milliseconds, such as `0.2s`, `300ms` or `0s`, or a CSS function such as `var(--duration)`.
```

The delay and the duration are separate arguments, so two times written into
one of them stop the build as well. A browser drops an `animation` carrying a
third time, which took the whole fade with it.

```scss
.a {
  @include loadify(0.2s 0.4s);
}
```
```text
Error: `0.2s 0.4s` is not a valid delay for `loadify`, which takes one time. A second one in the `animation` shorthand makes a browser drop the declaration, so nothing fades.
```

A negative duration is refused for the same reason, and it was the quieter of
the two: nothing was dropped, the two arguments simply swapped. Only a delay
may be negative, so `animation: loadify -1s 0.4s backwards` computes to a
duration of `0.4s` and a delay of `-1s` in Chrome 152, Firefox 156 and Safari
26.6.2 alike, which puts the fade behind the page rather than in front of it.
With both times negative all three drop the declaration outright.

```scss
.a {
  @include loadify(0.4s, -1s);
}
```
```text
Error: `-1s` is not a valid duration for `loadify`, which cannot be negative. Only a delay may be, so a browser reads the two the other way round: the duration becomes the delay and the fade is over before the page paints. Pass a positive duration, and a negative first argument if you want the fade to start part of the way in.
```

The two places the mixin is called are not interchangeable, and each now says
so. `init` writes the keyframes and belongs at the root; a delay and a duration
belong on the element. Written the wrong way round they used to fail with a
message about times, which named neither mode.

```scss
.a {
  @include loadify(init);
}
```
```text
Error: `init` goes at the root of the stylesheet, not inside a selector: it writes the keyframes once, and the call on an element takes a delay and a duration. Write `@include loadify(init);` outside any rule, and `@include loadify;` here.
```

```scss
@include loadify(0.4s);
```
```text
Error: `0.4s` is not a valid argument at the root of a stylesheet, where `loadify` writes the keyframes: pass `init`, or nothing. A delay and a duration belong on the call inside a selector, such as `.card { @include loadify(0.2s, 0.5s); }`.
```
