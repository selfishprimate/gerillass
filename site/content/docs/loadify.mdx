# Loadify

<Member name="loadify">

The **Loadify Sass mixin** is a handy tool that helps you make a page element load with a smooth fade-in effect while the page is loading.

<Hint kind="info">

**The element is visible by default, and the animation only fades it in.** The keyframes start at `opacity: 0` and `animation-fill-mode: backwards` applies that during the delay, so the fade looks the same as before while an animation that never runs leaves the content where it is. Under `prefers-reduced-motion: reduce` the mixin writes `animation: none`, and nothing else is needed.

</Hint>

</Member>

<KeepScroll />

<Hint kind="info">

**Refreshing keeps your place on this page.** The effect only runs when the page loads, so every example below asks you to refresh. This one page puts the scroll position back where it was, which the rest of the site does not do, so the demo you are looking at is the one that replays.

</Hint>

## Arguments

<Arguments of="loadify" footnote="The time value must be given in either seconds (s) or milliseconds (ms). The value must be zero or positive, and the unit is always required.">
  <Argument name="$mode" type="string">Accepts <code>init</code> at the root of your stylesheet, which writes the keyframes once. Since 4.0.0 a stylesheet that forgets it still builds: the elements simply do not fade.</Argument>
  <Argument name="$delay" type="time">Specifies the amount of time a design element must wait before it starts appearing on the page. The default value is set to <code>0.2s</code>.</Argument>
  <Argument name="$duration" type="time">Sets the length of time a page element takes to load. <strong>This is the second argument. It must always come last and cannot be used on its own.</strong> The default value is <code>0.5s</code>.</Argument>
</Arguments>

## Examples

```scss
@include loadify(init);
```
```css
//CSS Output
@keyframes loadify {
  from {
    opacity: 0;
  }
}
```

<Hint kind="info">

**Keep in mind!** You are free to give the element any selector name you want.

</Hint>

<Hint kind="info">

**Call `loadify(init)` once at the root**, to write the keyframes the elements animate to. Since 4.0.0 it can live in any file: the mixin no longer works by `@extend`, so the call and the initializer no longer have to see each other, and a stylesheet that leaves `init` out builds as before with no fade.

</Hint>

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** Until then the element was written as `opacity: 0; visibility: hidden` and the animation was the thing that revealed it, so anything that stopped the animation left the content invisible for good. Measured in Chrome 152, Firefox 156 and Safari 26.6.2 with a later `animation: none`, which a component or a reset can easily write: the element computed to `opacity: 0` and `visibility: hidden` in all three, gone from the page and from the accessibility tree with it. It now computes to `opacity: 1` and `visible` in all three.

</Hint>

<Hint kind="info">

**Important!** When you call the mixin inside a selector without passing any arguments, it works differently, as you can see in the example below. Here, the `item` selector takes the default `animation-delay` and `animation-duration` values.

</Hint>
