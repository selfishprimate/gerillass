# Fluid

<Member name="fluid">

A value that grows with the viewport between two widths and then stops. `fluid(24px, 48px)` is `24px` on a small screen, `48px` on a large one, and a straight line between the two.

<Hint kind="danger">

**This is why the function exists.** A fluid value written by hand usually comes out as pure `vw`, and a `vw`-only value ignores browser text zoom: raising the root font size moved this function's value from 20.83px to 34.17px, while the `vw`-only one stayed at 19.74px. That failure is [WCAG 1.4.4](https://www.w3.org/WAI/WCAG21/Understanding/resize-text.html); the preferred value here keeps a `rem` term so it does not.

</Hint>

<Hint kind="info">

**It is a function, not a mixin, so there is no `@include`.** The hard part is the value, and a value belongs to any property. `font-size` is the obvious one, but `padding`, `gap` and `margin` take it just as well.

</Hint>

</Member>

## How the value is built

The preferred value is the line through `(min-viewport, min)` and `(max-viewport, max)`.

```nix
slope     = (max - min) / (max-viewport - min-viewport)
intercept = min - slope * min-viewport
preferred = intercept + slope * 100vw
```

Checked against hand arithmetic at a real 900px viewport: the floor came out at 16.00px against 16.00 expected, the ceiling at 24.00 against 24.00, and an interpolated value at 19.52 against 19.52.

## Arguments

<Arguments of="fluid" footnote="Any absolute length works, and so does `rem`. A unit whose size the stylesheet cannot work out, such as `em`, `vw` or `%`, is refused: the line has to be built from real numbers.">
  <Argument name="$min" type="number (with unit)">An absolute length, <code>px</code>, <code>pt</code>, <code>pc</code>, <code>in</code>, <code>cm</code>, <code>mm</code> or <code>q</code>, or a <code>rem</code>. The value at <code>$min-viewport</code>.</Argument>
  <Argument name="$max" type="number (with unit)">The same units, and the value at <code>$max-viewport</code>, no smaller than <code>$min</code>.</Argument>
  <Argument name="$min-viewport (320px)" type="number (with unit)">The width below which the value stops shrinking.</Argument>
  <Argument name="$max-viewport (1280px)" type="number (with unit)">Larger than <code>$min-viewport</code>.</Argument>
</Arguments>

<Example caption="It composes too, because it is a value rather than a declaration. Inside `calc()` it is one term of a sum, which is how a container gets a margin that opens with the page while keeping the rest of the arithmetic.">
```scss
.measure {
  width: calc(100% - #{fluid(16px, 96px)});
  transform: translateY(fluid(2px, 12px));
}
```
</Example>

<Example caption="Your own viewport range, and values given in `rem`. A `rem` is turned into pixels against a 16px root, which is the one assumption the function makes and states.">
```scss
.stack {
  gap: fluid(0.5rem, 2rem, 20rem, 75rem);
}
```
</Example>

## What it refuses

Arguments are checked, so a wrong value stops the build with a message instead of quietly producing a value that never changes.

```scss
.title {
  font-size: fluid(16px, 24px, 1280px, 320px);
}
```
```text
Error: `fluid` needs $min-viewport to be smaller than $max-viewport, and was given 1280px and 320px.
```

```scss
.title {
  font-size: fluid(40px, 20px);
}
```
```text
Error: `fluid` needs $min to be no larger than $max, and was given 40px and 20px. clamp() would return the floor at every width, so the value would never grow.
```

```scss
.title {
  font-size: fluid(16, 24);
}
```
```text
Error: `16` is not a valid $min for `fluid`. Pass an absolute length such as `16px`, or a `rem`.
```

```scss
.title {
  font-size: fluid(1em, 2em);
}
```
```text
Error: `1em` is not a valid $min for `fluid`: `em` has no size this stylesheet can work out. Pass an absolute length such as `16px`, or a `rem`.
```

The absolute units are not in that group, and used to be refused with the same message although Sass converts between all of them: `fluid(12pt, 18pt)` is the same clamp as `fluid(16px, 24px)`, because 12pt is 16px. `rem` is the one exception, turned into px against a stated 16px root, since Sass has no way to know the real one.
