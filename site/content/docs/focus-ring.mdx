# Focus Ring

<Member name="focus-ring">

The **Focus Ring Sass mixin** draws the ring a keyboard user follows around the page. It writes an `outline` on `:focus-visible`, with a width, an offset and a colour.

That is two declarations, and both halves of the selector matter. The usual ways of doing this by hand either take the ring away from keyboard users or draw one that disappears in high contrast mode.

</Member>

## What goes wrong by hand

Measured in Chrome 152, on buttons, a link and a text input:

| Written by hand | What happens |
|---|---|
| `:focus { outline: none; }` | tabbing to the element shows nothing at all: no outline, no shadow |
| a ring on `:focus` | it also appears on every mouse click, which is why people remove it |
| a ring on `:focus-visible` | a mouse click on a button or a link does not show it; <kbd>Tab</kbd> does |
| a `box-shadow` ring instead of an outline | looks the same, but forced-colors mode sets `box-shadow` to `none` |

<Hint kind="warning">

**The ring must be an outline.** Forced-colors mode, which is how Windows High Contrast reaches CSS, removes box shadows and repaints the outline colour with a system colour. A shadow ring disappears for exactly the people who rely on it most, while an outline stays. This follows the CSS Color Adjustment specification; the browser used for the other measurements on this page could not emulate the mode.

</Hint>

<Hint kind="info">

**Form fields show the ring on a click too.** In Chrome 152 an input, a textarea and a select all match `:focus-visible` when clicked, not only when reached with <kbd>Tab</kbd>, because a browser expects the keyboard to be used next. That is the browser's decision, not the mixin's.

</Hint>

## Arguments

<Arguments of="focus-ring" footnote="The values are written straight into `outline` and `outline-offset`, so anything CSS accepts there works, including `var()`.">
  <Argument name="$width (2px)" type="number (with unit)">The thickness of the ring.</Argument>
  <Argument name="$offset (2px)" type="number (with unit)">The gap between the element and the ring. A negative value draws the ring inside the element.</Argument>
  <Argument name="$color (currentColor)" type="color">The colour of the ring. The default follows the text colour of the element, which is right for text and outlined controls and wrong for a filled button with light text, where the ring would come out white. Pass a colour there: a colour, <code>currentColor</code>, a system colour such as <code>Highlight</code>, or a function such as <code>var()</code> or <code>color-mix()</code>.</Argument>
</Arguments>

## Examples

<Example caption="Buttons. The outlined button keeps the default, because its text is dark. The filled button has light text, so `currentColor` would draw a white ring, and it is given a colour instead. **Click an empty spot in the result, then press the Tab key on your keyboard**: a click on a button itself does not show the ring, which is the point of `:focus-visible`.">
```scss
.btn-outline {
  @include focus-ring;
}

.btn-primary {
  @include focus-ring($color: #18181b);
}
```
```html
<style>
  .row { display: flex; flex-wrap: wrap; gap: 12px; align-items: center; }
  .btn {
    display: inline-flex; align-items: center; justify-content: center;

    cursor: pointer; transition: background-color .15s, border-color .15s;
  }

  .btn-outline:hover { background: #f4f4f5; }
</style>
<div class="row">
  <button class="btn btn-primary">Save changes</button>
  <button class="btn btn-outline">Cancel</button>
</div>
```
</Example>

```scss
  @include focus-ring(2px, 2px, #18181b);
}
```

<Hint kind="info">

**Inside a container with `overflow: hidden`, use a negative offset.** An outline drawn outside the element is clipped by that container: with a 2px offset only the corners of the ring were left showing. An offset of `-4px` draws it inside the element, where nothing clips it. The ring also follows `border-radius`, so a rounded button gets a rounded ring.

</Hint>

## What it refuses

A colour the outline drops stops the build, because a dropped outline means no ring at all, which is the failure this mixin exists to prevent. Measured in Chrome 152, `outline: 2px solid` drops a word that is not a colour, a quoted colour, a length, and a CSS-wide keyword, which only works as a whole declaration. Until 2.3.3 each of those compiled.

```scss
.element {
  @include focus-ring(2px, 2px, inherit);
}
```
```text
Error: `inherit` is not a valid $color for `focus-ring`: a CSS-wide keyword only works as a whole declaration, not inside this value. A browser drops the outline, so no ring is drawn. Pass a colour such as `#1a73e8`, `currentColor`, or a function such as `var(--focus)`.
```
