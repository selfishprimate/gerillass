# Background Image

<Member name="background-image">

The **Background Image** Sass mixin puts an image behind an element and, when
you pass colours, a filter over it. The image is written as a `background-image`
with `cover`, `center center` and `no-repeat`, so a photograph fills the box at
any size; one colour is a flat wash over it and several are a gradient.

Pass `null` for the image when it is already on the element in the markup. The
filter is then an `::after` layer over it, and the mixin lifts the element's
direct children above that layer, so a heading stays readable.

</Member>

## Arguments

<Arguments of="background-image" footnote="Use `null` if you want to skip an argument. See [the examples](#examples) for more.">
  <Argument name="$image-url" type="string, function">The URL of the background image, as a string. A value that already is an image, <code>var()</code>, <code>url()</code>, <code>image-set()</code> or a gradient, is written as it is rather than wrapped in <code>url()</code>. A list, a number, a colour or a boolean is refused.</Argument>
  <Argument name="$filter-color" type="color | list">The color or list of colors you want to apply as a filter over the background image. <strong>Multiple color values must be separated by a space.</strong> Several colours are the stops of a gradient and take the forms <a href="/docs/gradient">Gradient</a> takes. When <code>$image-url</code> is <code>null</code> and the image is set in the markup, the filter is a layer over it, so it can also be an image: a <code>linear-gradient()</code> for a scrim, a <code>radial-gradient()</code> for a vignette, or a <code>url()</code> for a pattern.</Argument>
  <Argument name="$filter-direction" type="string, number">The direction of the gradient, read when <code>$filter-color</code> has more than one colour. An angle such as <code>45deg</code> or <code>0.25turn</code>, a string such as <code>"to top right"</code>, or one of <code>top</code>, <code>top-right</code>, <code>right</code>, <code>bottom-right</code>, <code>bottom</code>, <code>bottom-left</code>, <code>left</code> and <code>top-left</code>. The default is <code>top</code>, and the value names where the last colour stop ends up. A value it does not accept is refused whatever the number of colours.</Argument>
</Arguments>

## Examples

<Example caption="The image alone, as a `background` that covers the element.">
```scss
.element {
  @include background-image("/images/backgrounds/07.jpg");
}
```
```html
<div class="element sandbox xlarge"></div>
```
</Example>

<Example caption="A colour over the image. One colour is a flat wash, and the alpha decides how much of the photograph is left.">
```scss
.element {
  @include background-image("/images/backgrounds/07.jpg", rgb(102 143 128 / 0.5));
}
```
```html
<div class="element sandbox xlarge"></div>
```
</Example>

<Example caption="Several colours become a gradient over the image, which is what makes a photograph safe to put text on.">
```scss
.element {
  @include background-image("/images/backgrounds/07.jpg", rgb(34 44 37 / 0.5) rgb(47 57 55 / 0.8));
}
```
```html
<div class="element sandbox xlarge"></div>
```
</Example>

<Example caption="`$filter-direction` turns that gradient. With `right` the last colour ends up on the right, so the teal is on that side and the dark end is on the left.">
```scss
.element {
  @include background-image("/images/backgrounds/07.jpg", rgb(47 57 55 / 0.7) rgb(91 192 187 / 0.8), right);
}
```
```html
<div class="element sandbox xlarge"></div>
```
</Example>

<Example caption="When the image is on the element in the markup, pass `null` for `$image-url`. The output is a different shape: the filter becomes an `::after` layer rather than a second `background-image`, so the two declarations cannot override each other." listing="<div class=&quot;element&quot; style=&quot;background-image: url(/images/backgrounds/07.jpg)&quot;></div>">
```scss
.element {
  @include background-image(null, rgba(#5bc0bb, 0.7) rgba(#bdc488, 0.8), right);
}
```
```html
<div class="element sandbox xxlarge" style="background-image: url(/images/backgrounds/07.jpg)"></div>
```
</Example>

<Example caption="A heading over that filter needs no rule of your own: the mixin writes `position: relative` and `z-index: 1` on the element's direct children, which is what keeps them above the `::after` layer." listing="<div class=&quot;element&quot; style=&quot;background-image: url(/images/backgrounds/07.jpg)&quot;>
&#32;&#32;<h2>A beautiful title text standing over the color filter.</h2>
</div>">
```scss
.element {
  @include background-image(null, rgba(#5bc0bb, 0.7) rgba(#bdc488, 0.8), right);
}
```
```html
<style>
  .element { padding: 20px; }
  .element h2 { margin: 0; font: 700 22px/1.3 Inter, ui-sans-serif, system-ui, sans-serif; color: #2f3937; }
</style>
<div class="element sandbox large" style="background-image: url(/images/backgrounds/07.jpg)">
  <h2>A beautiful title text standing over the color filter.</h2>
</div>
```
</Example>

## What it refuses

An image that is not one path stops the build. Until 2.3.1 anything went into `url()`: measured in Chrome 152, a list such as `url(16 9)` is dropped, and `url(42)` or `url(true)` is kept but asks for a file of that name, which is never the image meant.

```scss
.element {
  @include background-image(16 9);
}
```
```text
Error: `16 9` is not a valid $image-url for `background-image`: it is a list where one image is meant, and a browser drops `url()` with a list in it. Pass one path as a string, such as `"/img/hero.png"`.
```

A filter colour that is not a colour is refused too, since 2.3.1. Measured in Chrome 152, a word drops the filter, and a length written into `background` is read as a position rather than a colour.

```scss
.element {
  @include background-image("/img/a.png", huge);
}
```
```text
Error: `huge` is not a valid $filter-color for `background-image`: it is not a colour. Pass a colour, such as `rgba(0, 0, 0, 0.5)`, or several for a gradient.
```

A direction is checked whether or not there is a gradient to turn. It used to be
read only when there were two or more colours, so with one colour a typo was
dropped without a word.

```scss
.element {
  @include background-image("/img/a.png", red blue, sideways);
}
```
```text
Error: `sideways` is not a valid $filter-direction for `background-image`. Pass an angle such as `45deg` or `0.25turn`, `"to top right"`, or one of: top, top-right, right, bottom-right, bottom, bottom-left, left, top-left.
```
