# Background Image

<Member name="background-image">

The **Background Image** Sass mixin puts an image behind an element and, when
you pass colours, a filter over it. The image is written as a `background-image`
with `cover`, `center center` and `no-repeat`, so a photograph fills the box at
any size; one colour is a flat wash over it and several are a gradient.

Pass `null` for the image when it is already on the element in the markup. The
filter is then an `::after` layer over it, and the mixin lifts the element's
direct children above that layer, so a heading stays readable.

</Member>

## Arguments

<Arguments of="background-image" footnote="Use `null` if you want to skip an argument. See [the examples](#examples) for more.">
  <Argument name="$image-url" type="string, function">The URL of the background image, as a string. A value that already is an image, <code>var()</code>, <code>url()</code>, <code>image-set()</code> or a gradient, is written as it is rather than wrapped in <code>url()</code>, and so is <code>none</code>, the CSS keyword for no image at all. A list, a number, a colour or a boolean is refused. Pass <code>null</code> when the image is on the element in the markup.</Argument>
  <Argument name="$filter-color" type="color | list">The color or list of colors you want to apply as a filter over the background image. <strong>Multiple color values must be separated by a space.</strong> Several colours are the stops of a gradient and take the forms <a href="/docs/gradient">Gradient</a> takes. When <code>$image-url</code> is <code>null</code> and the image is set in the markup, the filter is a layer over it, so it can also be an image: a <code>linear-gradient()</code> for a scrim, a <code>radial-gradient()</code> for a vignette, or a <code>url()</code> for a pattern.</Argument>
  <Argument name="$filter-direction" type="string, number">The direction of the gradient, read when <code>$filter-color</code> has more than one colour. An angle such as <code>45deg</code> or <code>0.25turn</code>, a string such as <code>"to top right"</code>, or one of <code>top</code>, <code>top-right</code>, <code>right</code>, <code>bottom-right</code>, <code>bottom</code>, <code>bottom-left</code>, <code>left</code> and <code>top-left</code>. The default is <code>top</code>, and the value names where the last colour stop ends up. A value it does not accept is refused whatever the number of colours, and a value passed with one colour warns, since there is no gradient to turn.</Argument>
  <Argument name="$size" type="string, number">The <code>background-size</code>. <code>cover</code>, the default, <code>contain</code>, <code>auto</code>, one or two lengths or percentages, or a <code>var()</code> or <code>calc()</code>. A negative length is refused, since a browser drops the declaration. <code>null</code> leaves the declaration out.</Argument>
  <Argument name="$position" type="string, number">The <code>background-position</code>. <code>center center</code> by default, and it takes what the property takes: <code>left</code>, <code>center</code>, <code>right</code>, <code>top</code>, <code>bottom</code>, lengths and percentages, up to the four-value form such as <code>right 10px bottom 20px</code>. <code>null</code> leaves the declaration out.</Argument>
  <Argument name="$repeat" type="string">The <code>background-repeat</code>. <code>no-repeat</code> by default, or <code>repeat</code>, <code>repeat-x</code>, <code>repeat-y</code>, <code>space</code>, <code>round</code>, or two of them, one per axis. <code>null</code> leaves the declaration out.</Argument>
</Arguments>

## What it refuses

An image that is not one path stops the build. Until 2.3.1 anything went into `url()`: measured in Chrome 152, a list such as `url(16 9)` is dropped, and `url(42)` or `url(true)` is kept but asks for a file of that name, which is never the image meant.

```scss
.element {
  @include background-image(16 9);
}
```
```text
Error: `16 9` is not a valid $image-url for `background-image`: it is a list where one image is meant, and a browser drops `url()` with a list in it. Pass one path as a string, such as `"/img/hero.png"`.
```

A filter colour that is not a colour is refused too, since 2.3.1. Measured in Chrome 152, a word drops the filter, and a length written into `background` is read as a position rather than a colour.

```scss
.element {
  @include background-image("/img/a.png", huge);
}
```
```text
Error: `huge` is not a valid $filter-color for `background-image`: it is not a colour. Pass a colour, such as `rgba(0, 0, 0, 0.5)`, or several for a gradient.
```

A size the browser drops is refused as well. A negative `background-size` is
dropped in Chrome 152, Firefox 156 and Safari 26.6.2, and so is a word that is
not one of the three keywords.

```scss
.element {
  @include background-image("/img/a.png", null, null, -10px);
}
```
```text
Error: `-10px` is not a valid $size for `background-image`: `-10px` is below zero. A browser drops the declaration and the image falls back to its own size.
```

A direction is checked whether or not there is a gradient to turn. It used to be
read only when there were two or more colours, so with one colour a typo was
dropped without a word.

```scss
.element {
  @include background-image("/img/a.png", red blue, sideways);
}
```
```text
Error: `sideways` is not a valid $filter-direction for `background-image`. Pass an angle such as `45deg` or `0.25turn`, `"to top right"`, or one of: top, top-right, right, bottom-right, bottom, bottom-left, left, top-left.
```

## What it warns about

A direction turns a gradient, and one colour is a flat wash with nothing to
turn. The value is left out of the output rather than written as `to top`,
and the build says so.

```scss
.element {
  @include background-image("/img/a.png", rgba(0, 0, 0, 0.5), right);
}
```
```text
WARNING: `$filter-direction` is only read when `$filter-color` has more than one colour, so `right` was left out of `background-image`.
```
