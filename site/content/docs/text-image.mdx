# Text Image

<Member name="text-image">

The **Text Image** Sass mixin helps you clip the background image of a selected element to the shape of its foreground text. 

</Member>

## Arguments

<Arguments of="text-image" footnote="**Important:** Pass the URL of the image in quotation marks. A `var()`, `url()`, `image-set()` or gradient is written as it is, without quotes.">
  <Argument name="$image" type="string (quoted), function">The URL of the clipping image. A value that already is an image, <code>var()</code>, <code>url()</code>, <code>image-set()</code> or a gradient, is written as it is rather than wrapped in <code>url()</code>. A list, a number, a colour or a boolean is refused.</Argument>
  <Argument name="$fallback" type="color">The colour the letters take when the image does not arrive, written as a <code>background-color</code> under it. Without one, an image that fails to load leaves no visible text at all.</Argument>
</Arguments>

## Examples

<Example caption="The image is passed to the mixin and shows through the letters, which is what a display headline does with a photograph." listing="<h2 class=&quot;element&quot;>Text Image is Awesome!</h2>">
```scss
.element {
  @include text-image("/images/landscape.webp");
}
```
```html
<style>
  body { background: #f8fafc; }
  .element { margin: 0; font: 800 56px/1.05 Inter, ui-sans-serif, system-ui, sans-serif; letter-spacing: -0.03em; }
</style>
<h2 class="element">Summer issue</h2>
```
</Example>

<Example caption="The `$image` argument is optional. This is especially useful when the image is loaded from the markup, as in the example below." listing="<h2 class=&quot;element&quot; style=&quot;background-image: url(/images/landscape.webp)&quot;>Text Image is Awesome!</h2>">
```scss
.element {
  @include text-image;
}
```
```html
<style>
  body { background: #f8fafc; }
  .element { margin: 0; font: 800 56px/1.05 Inter, ui-sans-serif, system-ui, sans-serif; letter-spacing: -0.03em; }
</style>
<h2 class="element" style="background-image: url(/images/landscape.webp)">Golden hour</h2>
```
</Example>

<Example caption="Pass a `$fallback` colour and the letters have something to fall back to. The colour goes under the image as a `background-color`, so it fills them whenever the image does not arrive: a 404, a blocked host, a slow connection." listing="<h2 class=&quot;title&quot;>Text Image is Awesome!</h2>">
```scss
.title {
  @include text-image("/images/landscape.webp", $fallback: #0369a1);
}
```
```html
<style>
  body { background: #f8fafc; }
  .title { margin: 0; font: 800 56px/1.05 Inter, ui-sans-serif, system-ui, sans-serif; letter-spacing: -0.03em; }
</style>
<h2 class="title">Golden hour</h2>
```
</Example>

<Hint kind="danger">

**Without a fallback, an image that does not load takes the text with it.** The mixin makes the letters transparent and the image is the only thing painting them. Measured in Chrome 152 with a path that 404s: the box was pixel for pixel one whose text is transparent and which has no background at all, so a broken image is not a broken image, it is a lost heading. With `$fallback` the same box rendered its letters in that colour.

</Hint>

<Hint kind="info">

**Forced colours are handled since 4.0.0.** In that mode the browser forces `background-image: none` and forces `color`, but `-webkit-text-fill-color` is not a forced property, so the transparent fill survived and the text disappeared. The mixin now writes a `@media (forced-colors: active)` block that gives both properties back: measured with forced colours on, the computed fill colour was `rgba(0, 0, 0, 0)` before and is black now, in Chrome 152 and Firefox 156.

</Hint>

## What it refuses

An image that is not one path stops the build. Until 2.3.1 anything went into `url()`, and here that matters more than elsewhere: the mixin makes the text transparent, so an image that does not load leaves no visible text at all. Measured in Chrome 152, a list such as `url(16 9)` is dropped.

```scss
.element {
  @include text-image(16 9);
}
```
```text
Error: `16 9` is not a valid $image for `text-image`: it is a list where one image is meant, and a browser drops `url()` with a list in it. Pass one path as a string, such as `"/img/hero.png"`.
```
