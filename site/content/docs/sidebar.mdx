# Sidebar

<Member name="sidebar">

The **Sidebar** Sass mixin lays out a sidebar beside a content column and lets the two stack when the space runs out. There is no media query in it and no breakpoint to choose: the layout reacts to the box it is in.

</Member>

<Hint kind="warning">

**New in Gerillass 4.0.0.**

</Hint>

## What it is for

A media query reads the window, and a sidebar layout usually lives inside something narrower than the window: a card, one pane of a split view, an embedded widget, or a documentation page whose content column has a menu beside it.

Measured in Chrome 152, Firefox 156 and Safari 26.6.2, with the window at 1024px so that `@media (max-width: 768px)` never fires, and the same two column layout put into boxes of different widths:

| The box | `grid-template-columns: 20rem 1fr` with a 768px query | `sidebar` |
|---|---|---|
| 1000px | 320 + 656 | 337 + 639 |
| 700px | 320 + **356** | stacked, 700 + 700 |
| 560px | 320 + **216** | stacked, 560 + 560 |
| 400px | 320 + **60**, and 4px of overflow | stacked, 400 + 400 |

All three browsers agreed on every row. The query is looking at the window, which is wide, while the box is not.

## Arguments

<Arguments of="sidebar" footnote="The mixin goes on the parent, and it styles that element's first and last child.">
  <Argument name="$side" type="number">How wide the sidebar is while the two sit in a row, <code>20rem</code> by default. It is the sidebar's <code>flex-basis</code>, so it also takes <code>auto</code>, <code>content</code>, the intrinsic keywords, a <code>var()</code> or a <code>calc()</code>.</Argument>
  <Argument name="$gap" type="number">The gap between the two, and between the rows once they stack. <code>1.5rem</code> by default.</Argument>
  <Argument name="$threshold" type="number">The share of the row the content may not go under before the two stack, <code>50%</code> by default. A proportion rather than a width, which is what makes the layout follow its box. A larger value stacks sooner.</Argument>
  <Argument name="$side-on" type="string"><code>left</code>, the default, or <code>right</code>. It names the side the sidebar sits on, and the mixin swaps which child is which.</Argument>
</Arguments>

## The three declarations that carry it

```css
.layout {
  display: flex;
  flex-wrap: wrap;
  gap: 1.5rem;
}
.layout > :first-child {
  flex-basis: 20rem;
  flex-grow: 1;
}
.layout > :last-child {
  flex-basis: 0;
  flex-grow: 999;
  min-inline-size: 50%;
}
```

- **`flex-grow: 999`** on the content is why the sidebar stays at its width. The content takes every spare pixel, so there is none left to widen the sidebar with. Written as `flex: 1` on both, the two share the spare space and the sidebar grows with the window.
- **`flex-basis: 0`** on the content keeps its own width out of the sum, so the row is the sidebar plus whatever is left.
- **`min-inline-size`** is the threshold. A flex item may not go under it, so when the content would, the row wraps and the two stack. It is a share of the row rather than a pixel width, which is what makes the layout follow its box instead of the window.

<Hint kind="info">

**It styles the first and the last child.** A third element between them is laid out by flexbox's own defaults, which is rarely what a sidebar layout wants. `$side-on` swaps which of the two is the sidebar, and leaves the markup order alone, so the content can come first for a screen reader while being drawn second.

</Hint>

## What it refuses

```scss
.layout {
  @include sidebar(20);
  @include sidebar(20rem, -1rem);
  @include sidebar(20rem, 1.5rem, fit-content(20rem));
  @include sidebar(20rem, 1.5rem, 50%, middle);
}
```
```text
Error: `20` is not a valid $side for `sidebar`: a unitless number is not a length; add a unit, such as `20px`. It is the sidebar's `flex-basis`, and a browser drops the declaration.
Error: `-1rem` is not a valid $gap for `sidebar`: a length below zero does not work here. A browser drops the declaration and the two columns touch.
Error: `fit-content(20rem)` is not a valid $threshold for `sidebar`: `fit-content()` does not give a length here. It is the content's `min-inline-size`, the share of the row below which the two stack, and a browser drops the declaration.
Error: `middle` is not a valid $side-on for `sidebar`. Pass `left` or `right`, which is the side the sidebar is on while the two sit in a row.
```

The keyword lists behind those checks were measured rather than assumed, in all three browsers, with a working value written before the one under test: `flex-basis` keeps `auto`, `content` and the intrinsic keywords, `min-inline-size` keeps `auto`, `min-content` and `max-content` but drops `fit-content()`, and both drop a unitless number, a negative length and a word. `min-inline-size: stretch` is kept by Chrome alone, so it is not on the list.
