# Shorthand Property

<Member name="shorthandProperty">

Expands one to four values into the four-value CSS shorthand order.

</Member>

## Arguments

<Arguments of="shorthandProperty">
  <Argument name="$value" type="list">Accepts one to four values.</Argument>
</Arguments>

## Examples

<Example caption="One to four values expanded to the full four-value shorthand.">
```scss
.card {
  padding: shorthandProperty(16px 24px);
}
```
</Example>

<Example caption="A `null` is carried through to the position it belongs in, which is what lets a caller skip a side. [Position](/docs/position) reads the four values back and writes a declaration only for the ones that are set.">
```scss
.card {
  padding: shorthandProperty(16px);
  margin: shorthandProperty(8px 12px 16px);
}
```
</Example>

## What it refuses

Arguments are checked, so a wrong value stops the build with a message instead of quietly producing the wrong CSS.

```scss
.card {
  padding: shorthandProperty(1px 2px 3px 4px 5px);
}
```
```text
Error: `shorthandProperty` was given 5 values. Pass one to four, in the order CSS reads them: all, block and inline, top and sides and bottom, or top right bottom left.
```

An empty list and a map raise as well.

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** Only a fifth value used to be checked. An empty list ended the build with Sass's own "Function finished without @return", and a map was read as its keys and values in turn, so `(a: 1, b: 2)` came out as `a 1 b 2 a 1 b 2`. A `null` is still passed through, on purpose.

</Hint>
