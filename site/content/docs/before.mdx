# Before

<Member name="before">

The **Before** Sass mixin helps you generate content or a style element before the actual content of the selected element or elements.

</Member>

## Arguments

<Arguments of="before" footnote="To render the value of a data attribute, pass its name, which must start with `data-`. See the examples for more.">
  <Argument name="$content" type="string, function">You can pass content as a string, or the name of a data attribute such as <code>data-content</code> to render its value. A CSS function, <code>var()</code>, <code>attr()</code>, <code>counter()</code> or <code>counters()</code>, is written as it is rather than quoted into text. With no argument the mixin writes an empty <code>content</code> that anything else sets overrides; see below.</Argument>
</Arguments>

## Examples

<Example caption="Simply pass a value as a string.">
```scss
.total {
  @include before("Total: ");
}
```
```html
<style>
  body { background: #f8fafc; font: 15px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #0f172a; }
  .row { display: flex; justify-content: space-between; width: 260px; padding: 16px 18px; border-radius: 14px; background: #fff; box-shadow: 0 6px 20px rgb(15 23 42 / 0.08); font-weight: 700; }
  .total::before { color: #64748b; font-weight: 600; }
</style>
<div class="row"><span class="total"></span><span>$228.00</span></div>
```
</Example>

<Example caption="You can target the `::before` pseudo-element on its own and pass a declaration block.">
```scss
.note {
  @include before {
    content: "Note ";
    font-weight: 700;
    font-style: normal;
    color: #b45309;
  }
}
```
```html
<style>
  body { background: #f8fafc; font: 15px/1.6 Inter, ui-sans-serif, system-ui, sans-serif; color: #0f172a; }
  .note { display: block; max-width: 420px; padding: 14px 16px; border-radius: 12px; background: #fffbeb; color: #78350f; font-style: italic; }
</style>
<em class="note">the trial ends on the first of the month, and nothing is charged before then.</em>
```
</Example>

<Example caption="You can render the value of a data attribute. One important thing to remember is that the name of the attribute must start with the 'data-' prefix." listing="<div class=&quot;element&quot; data-currency=&quot;&#36;&quot;>200</div>">
```scss
.element{
  @include before("data-currency");
}
```
```html
<style>
  .element { font: 600 20px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
</style>
<div class="element" data-currency="&#36;">200</div>
```
</Example>

<Example caption="You can pass a value for the CSS content property as a string, and a declaration block between the opening and closing curly braces." listing="<div class=&quot;element&quot; data-currency=&quot;&#36;&quot;>200</div>">
```scss
.element{
  @include before("data-currency"){
    margin-right: 2px;
    font-size: .6em;
    vertical-align: top;
    color: red;
  };
}
```
```html
<style>
  .element { font: 600 20px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
</style>
<div class="element" data-currency="&#36;">200</div>
```
</Example>

## Interface examples

<Example caption="Custom list markers. The list keeps its semantics, and the marker is whatever string you pass.">
```scss
.checklist li {
  @include before("✓") {
    margin-right: 8px;
    font-weight: 700;
    color: #16a34a;
  }
}
```
```html
<style>
  .checklist { list-style: none; margin: 0; padding: 0; display: grid; gap: 8px; font: 14px/1.4 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
</style>
<ul class="checklist">
  <li>Compiles with Dart Sass</li>
  <li>Zero runtime dependencies</li>
  <li>Tested in three browsers</li>
</ul>
```
</Example>

<Example caption="Numbered steps with CSS's own `counter()` function, which the mixin writes as it is rather than quoting it into text. `counter-reset` on the list creates the counter, and `counter-increment` on each step advances it; both are plain CSS." listing="<div class=&quot;steps&quot;>
  <div class=&quot;step&quot;>Install the package</div>
  <div class=&quot;step&quot;>Load it in your stylesheet</div>
  <div class=&quot;step&quot;>Include a mixin</div>
</div>">
```scss
.steps {
  counter-reset: step;
}

.step {
  counter-increment: step;
  @include before(counter(step)) {
    display: inline-flex;
    align-items: center;
    justify-content: center;
    width: 24px;
    height: 24px;
    margin-right: 10px;
    border-radius: 50%;
    background: #18181b;
    color: #fafafa;
    font-size: 12px;
    font-weight: 600;
  }
}
```
```html
<style>
  .steps { display: grid; gap: 10px; font: 14px/1.4 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
  .step { display: flex; align-items: center; }
</style>
<div class="steps">
  <div class="step">Install the package</div>
  <div class="step">Load it in your stylesheet</div>
  <div class="step">Include a mixin</div>
</div>
```
</Example>

<Hint kind="info">

**This `counter()` is not the [Counter](/docs/counter) mixin.** `counter(step)` above is the CSS function that reads a counter's current value, and `before` passes it through, as it does `var()`, `attr()` and `counters()`. The counter itself, `step`, is created by `counter-reset: step` on the list and advanced by `counter-increment: step` on each item, which you write yourself, as in the Sass above.

The Counter mixin does all three for you: it resets a counter on the element you include it in, advances it on each child, and writes the number into that child's `::before`, with optional text around it and your styles in the block. Reach for it when numbering a list is the whole job. Use `before` with `counter()` when the number is one part of a longer `content`, or when the element that shows the number is not the one being counted.

</Hint>

## Drawing with no content

<Example caption="A status dot before a label. With no argument the mixin writes `content: &quot;&quot;` for you, so a block of styles alone draws the dot. Until 4.0.0 this drew nothing, because a pseudo-element with no `content` is not rendered.">
```scss
.status {
  @include before {
    display: inline-block;
    width: 8px;
    height: 8px;
    margin-right: 8px;
    border-radius: 50%;
    background: #22c55e;
  }
}
```
```html
<style>
  .status { display: inline-flex; align-items: center; font: 500 14px/1 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
</style>
<span class="status">All systems operational</span>
```
</Example>

<Example caption="Coloured quotation marks on a `q` element. The browser draws the marks through `::before` and `::after`, and the default would replace them with nothing, so the block keeps them with `open-quote`.">
```scss
q {
  @include before {
    content: open-quote;
    color: #2563eb;
  }
}
```
```html
<style>
  p { font: 16px/1.5 Georgia, serif; color: #18181b; }
</style>
<p>She wrote back: <q>It works in all three browsers.</q></p>
```
</Example>

<Hint kind="warning">

**What the default overrides, and what it does not.** Measured in Chrome 152, Firefox 156 and Safari 26.6.2: the default is written as `:where(.status)::before`, which has only the pseudo-element's specificity, so a `content` in the block, or in any rule for the element with a class or an element selector, before or after the include, still wins. Three things lose to it. A `content` that only comes from another state, such as `:hover` or a media query, leaves the empty box drawn the rest of the time, so write `content: none` in the block. On a `q` element it replaces the browser's quotation marks, which the example above keeps with `open-quote`. And a bare `::before { content: ... }` rule written before the include loses, since both have the same specificity.

</Hint>
