# Truncate

<Member name="truncate">

The **Truncate** Sass mixin cuts text off where it runs out of room: one line ending in an ellipsis, or several lines ending in one. You say how many lines you want, and the mixin writes the technique that does it.

</Member>

<Hint kind="warning">

**New in Gerillass 4.0.0.** This replaces **Ellipsis** and **Line Clamp**, which are both removed. `truncate` is the old `ellipsis` and `truncate(3)` is the old `line-clamp(3)`, both compiling to exactly the CSS they did. See the migration guide.

</Hint>

## Arguments

<Arguments of="truncate" footnote="One line and several lines are different techniques, so a couple of the arguments only apply to one of them.">
  <Argument name="$lines" type="number | keyword">How many lines to keep. <code>1</code> is the default and gives the one-line ellipsis; a larger whole number clamps to that many lines; <code>none</code> undoes a clamp, which is what a media query needs. A <code>var()</code> is written as it is, since the browser resolves it.</Argument>
  <Argument name="$width" type="number">A <code>max-width</code> for the element. One line defaults to <code>100%</code>, because an inline box ignores a width it was never given; several lines write no width unless you pass one.</Argument>
  <Argument name="$display" type="string">The display for the one-line form, <code>inline-block</code> by default. Passing it with more than one line raises: the clamp takes the display over.</Argument>
</Arguments>

## Why the line count changes the technique

One line is `white-space: nowrap` with `text-overflow: ellipsis`, and the element keeps whatever display you give it. Several lines is the `-webkit-box` trio, which takes the display over. Measured in Chrome 152, Firefox 156 and Safari 26.6.2, on a 320px box:

| | One line | Three lines |
|---|---|---|
| Lines drawn | 1 | 3 |
| Ellipsis | yes | yes |
| The element's `display` | what you set, `inline-block` by default | `-webkit-box` in Safari, `flow-root` in Chrome and Firefox |

So at one line the two look the same and differ in what the element becomes, which is why the mixin writes one or the other rather than letting you pick both.

## Examples

<Example caption="One line. The default, and the shortest call there is." listing="<h4 class=&quot;title&quot;>A headline long enough to run out of room on one line</h4>">
```scss

  @include truncate;
}
```
```html
<style>
  .title { margin: 0; width: 320px; font: 700 18px/1.4 Inter, ui-sans-serif, system-ui, sans-serif; }
</style>
```

</Example>

<Example caption="`none` undoes a clamp, which is how a summary opens up on a wider screen." listing="<p class=&quot;teaser&quot;>On a narrow screen this is two lines and then an ellipsis. From the large breakpoint up, the clamp is lifted and the whole paragraph is shown.</p>">

</Example>

## What it refuses

A line count a browser cannot use stops the build, and so does an argument that belongs to the other technique.

```scss
.a { @include truncate(0); }
.b { @include truncate(1.5); }
.c { @include truncate(3px); }
.d { @include truncate(3, 100%, block); }
```

```text
Error: `0` is not a valid $lines for `truncate`. Pass a whole number of lines that is at least 1, or `none` to undo a clamp.
Error: `$display` does nothing for `truncate(3)`: clamping more than one line takes the display over, and the element is drawn as a box. Pass `$display` with one line, or leave it out.
```

<Hint kind="info">

**All five declarations of the clamp are needed.** Measured on a paragraph running to five lines, clamped to three: without `-webkit-box-orient: vertical`, without `display: -webkit-box`, or with the standard `line-clamp` alone, all five lines were drawn and nothing warned; without `overflow: hidden` the box was three lines tall and the rest of the text spilled out below it. `CSS.supports("line-clamp: 3")` still answers false in Chrome 152, Firefox 156 and Safari 26.6.2, so the standard property is written for the future and the prefixed trio does the work.

</Hint>
