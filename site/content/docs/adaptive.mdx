# Adaptive

<Member name="adaptive">

The **Adaptive Sass mixin** helps you set a `max-width` value on your container elements, based on the `breakpoint` values defined in the `_map-for-breakpoints.scss` file. It also takes a `$gutter` value, which sets how close the edges of the browser screen can get to the edges of the selected element.
<Hint kind="info">

**Tip:** The Adaptive mixin works best with `percentage` values.

</Hint>

</Member>

## What is Adaptive Design?

**Adaptive design** is a graphical user interface design approach that responds differently to various device screen sizes. It typically uses several fixed layout sizes, and when it detects the device size, it selects the best layout for that specific screen size.

The **Adaptive Sass mixin** gives you the fastest and most consistent way to apply adaptive design.

## Arguments

<Arguments of="adaptive" footnote="Apply this mixin to the container element of your layout, then narrow or widen your browser window to test it!">
  <Argument name="$gutter" type="number (with unit)">Accepts one value and applies it to all the breakpoints. The default value is <code>30px</code>. A length, a percentage, a negative length, <code>var()</code> or a maths function. <code>0</code> is written as <code>0px</code>, because the gutter is subtracted inside <code>calc()</code>.</Argument>
</Arguments>

## What it refuses

A gutter the browser drops stops the build. It is subtracted inside `calc()` at every breakpoint, and measured in Chrome 152 a word, a CSS-wide keyword, a unitless number and a unit that is not a length each drop the `max-width`, leaving the container at full width. Until 2.3.1 these compiled. `adaptive(0)` used to be one of them, `calc(576px - 0 * 2)`, and is now written with `0px`.

```scss
.main-container {
  @include adaptive(auto);
}
```
```text
Error: `auto` is not a valid $gutter for `adaptive`: it is not a length. A browser drops the max-width at every breakpoint.
```

<Hint kind="info">

**Changed in Gerillass 4.0.0.** The mixin skips a breakpoint of zero by its value rather than by the name `xsmall`. `$map-for-breakpoints` is a `!default` variable, so a project can name its own breakpoints, and a renamed zero entry used to stay in the list: the mixin wrote `@media (min-width: 0)` with `max-width: calc(0 - 30px * 2)` inside it. Written as `0px` in the map that calculation is valid, computes to -60px, and the browser clamps it to 0, so the container was 0 wide at every size. Measured in Chrome 152, Firefox 156 and Safari 26.6.2 with such a map: the container was 0 before and is the full width of the screen now. With the default map the CSS is exactly what it always was.

</Hint>

<Hint kind="info">

**There is one more step since Gerillass 4.0.0.** `$map-for-breakpoints` gained an `xxl` key at 1400px, so the mixin writes a fifth `@media` block and a container goes on growing past 1200px instead of stopping at 1140px. A project that sets its own map is unaffected, and one that wants the old ceiling can leave `xxl` out of it.

</Hint>
