# Adaptive

<Member name="adaptive">

The **Adaptive Sass mixin** helps you set a `max-width` value on your container elements, based on the `breakpoint` values defined in the `_map-for-breakpoints.scss` file. It also takes a `$gutter` value, which sets how close the edges of the browser screen can get to the edges of the selected element.
<Hint kind="info">

**Tip:** The Adaptive mixin works best with `percentage` values.

</Hint>

</Member>

## What is Adaptive Design?

**Adaptive design** is a graphical user interface design approach that responds differently to various device screen sizes. It typically uses several fixed layout sizes, and when it detects the device size, it selects the best layout for that specific screen size.

The **Adaptive Sass mixin** gives you the fastest and most consistent way to apply adaptive design.

## Arguments

<Arguments of="adaptive" footnote="Apply this mixin to the container element of your layout, then narrow or widen your browser window to test it!">
  <Argument name="$gutter" type="number (with unit)">Accepts one value and applies it to all the breakpoints. The default is <code>0</code>, so the container is exactly the breakpoint wide; a zero is written as the width itself rather than as a subtraction. A length, a percentage, a negative length, <code>var()</code> or a maths function. <code>0</code> is written as <code>0px</code>, because the gutter is subtracted inside <code>calc()</code>.</Argument>
</Arguments>

## Examples

<Example resizable caption="The result box is a viewport of its own, so drag its corner. The container is centred, and with the default gutter of `0` it is exactly the breakpoint wide: the band inside reaches both of its edges, and below `small` there is no maximum at all. Between two breakpoints the container stays where it is while the page grows around it, and that is the step." >
```scss
.main-container{
  @include adaptive;
}
```

  .band span { font-size: 13px; color: #dee0cd; }
  .text { padding: 18px 20px; }
  .text h3 { margin: 0 0 6px; font: 700 18px Inter, ui-sans-serif, system-ui, sans-serif; }
  .text p { margin: 0; color: #657167; }
</style>
<div class="main-container">
  <div class="band"><b>Sold out</b><span>Next show on Friday</span></div>
  <div class="text">

## What it refuses

A gutter the browser drops stops the build. It is subtracted inside `calc()` at every breakpoint, and measured in Chrome 152 a word, a CSS-wide keyword, a unitless number and a unit that is not a length each drop the `max-width`, leaving the container at full width. Until 2.3.1 these compiled. `adaptive(0)` used to be one of them, `calc(576px - 0 * 2)`; a zero gutter is not written as a subtraction at all now, and is the default.

```scss
.main-container {
  @include adaptive(auto);
}
```
```text
Error: `auto` is not a valid $gutter for `adaptive`: it is not a length. A browser drops the max-width at every breakpoint.
```

<Hint kind="info">

**Changed in Gerillass 4.0.0.** A breakpoint of zero is skipped by its value rather than by the name `xsmall`, so a project that names its own breakpoints keeps its container. With the default map the CSS is what it always was.

</Hint>

<Hint kind="info">

**There is one more step since Gerillass 4.0.0.** `$map-for-breakpoints` gained an `xxl` key at 1400px, so the mixin writes a fifth `@media` block and a container goes on growing past 1200px instead of stopping at 1140px. A project that sets its own map is unaffected, and one that wants the old ceiling can leave `xxl` out of it.

</Hint>
