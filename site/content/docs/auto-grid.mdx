# Auto Grid

<Member name="auto-grid">

The **Auto Grid** Sass mixin lays out as many columns as the container holds, each at least `$min` wide, and it does it without the overflow the usual one-liner produces on a narrow screen. `$limit` puts a ceiling on how many columns there may be.

</Member>

<Hint kind="warning">

**New in Gerillass 4.0.0.**

</Hint>

## The line it replaces

Almost every article about responsive grids gives you this:

```css
.cards {
  display: grid;
  gap: 1rem;
  grid-template-columns: repeat(auto-fit, minmax(20rem, 1fr));
}
```

It works until the container is narrower than the minimum, and then it breaks in a way nobody sees on a laptop. Measured in Chrome 152, Firefox 156 and Safari 26.6.2, in a container 250px wide:

| Track minimum | Column | Container |
|---|---|---|
| `minmax(20rem, 1fr)` | 320px | overflows by **70px** |
| `minmax(min(100%, 20rem), 1fr)` | 250px | fits |

All three browsers agree. `minmax()` takes its first value as a hard minimum, so the track never shrinks below it and the container is what gives, which on a phone is a horizontal scrollbar. Capping the minimum with `min(100%, …)` is the whole fix, and it is what this mixin writes.

## Arguments

<Arguments of="auto-grid" footnote="Every argument has a default, so `auto-grid` on its own is a working grid of 16rem columns with a 1rem gap.">
  <Argument name="$min" type="number">How narrow a column may be before the grid wraps to fewer of them. A length, a percentage, a <code>var()</code> or a <code>calc()</code>. The default is <code>16rem</code>. A keyword such as <code>min-content</code> is refused: it goes inside <code>min()</code>, which takes no keyword, and a browser drops the whole track list.</Argument>
  <Argument name="$gap" type="number">The gap between rows and columns, <code>1rem</code> by default. A length, a percentage, <code>normal</code>, a <code>var()</code> or a <code>calc()</code>.</Argument>
  <Argument name="$limit" type="number">A ceiling on the number of columns. A whole number, or nothing for as many as fit. It is arithmetic in the track formula, so a <code>var()</code> cannot be used here.</Argument>
  <Argument name="$fill" type="boolean">
    <code>true</code> writes <code>auto-fill</code>, which keeps an empty column standing; the default <code>false</code> writes <code>auto-fit</code>, which collapses it and lets the items stretch.
  </Argument>
</Arguments>

```scss
  @include auto-grid;
}
```

## auto-fit or auto-fill

The two differ only when there are fewer items than columns that would fit. Measured with two items in a 1000px container, a 15rem minimum and a 1rem gap:

| | Columns | Each |
|---|---|---|
| `auto-fit`, the default | 2 | 492px, the items stretch |
| `auto-fill`, with `$fill: true` | 3 | 323px, the third stands empty |

Chrome 152, Firefox 156 and Safari 26.6.2 agree, to within the sub-pixel each engine rounds to.

## What `$limit` writes

A ceiling on the column count is not a property. It comes out of the track minimum, which has to grow until only that many columns fit:

```scss
.team {
  @include auto-grid(10rem, 1rem, 4);
}
```

```css
.team {
  display: grid;
  gap: 1rem;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, max(10rem, (100% - 3 * 1rem) / 4)), 1fr));
}
```

The `3` and the `4` both follow `$limit`, and the `1rem` follows `$gap`, which is why this is worth a mixin: written by hand, changing the limit means editing the same expression in three places. Measured in a 1000px container with six items, all three browsers lay out exactly four 238px columns; in a 250px container the same call lays out one 250px column, because the `min(100%, …)` is still there.

<Hint kind="info">

**It writes nothing on the children.** `columnizer` needs `min-inline-size: 0` on its columns, and this was measured rather than copied: with a long unbroken token in a 250px container the track stayed 250px with and without that declaration, in all three browsers. A grid track whose minimum is given does not take its children's minimum content.

</Hint>

## What it refuses

```scss
.cards {
  @include auto-grid(min-content);
  @include auto-grid(20rem, -1rem);
  @include auto-grid(20rem, 1rem, 0);
}
```
```text
Error: `min-content` is not a valid $min for `auto-grid`: it is not a length. It is the smallest a column may be, and a browser drops the whole track list.
Error: `-1rem` is not a valid $gap for `auto-grid`: a length below zero does not work here. A browser drops the declaration and the columns touch.
Error: `0` is not a valid $limit for `auto-grid`. Pass a whole number of columns that is at least 1.
```

Each refusal was measured before it was written. In all three browsers a keyword in the track minimum, a negative gap and a word for a gap each drop the declaration they are in, while a length, a percentage, a `var()` and a `calc()` are kept.
