# Shade

<Member name="shade">

Mixes a colour towards black by a percentage.

</Member>

## Arguments

<Arguments of="shade">
  <Argument name="$color" type="color">A single colour, from any colour space. A list is refused, and so are <code>var()</code> and <code>currentColor</code>, which this stylesheet cannot read.</Argument>
  <Argument name="$percentage" type="number (percentage)">How far towards black to mix, from <code>0%</code> to <code>100%</code>. A unitless number is read as that many per cent, so <code>20</code> and <code>20%</code> are the same call.</Argument>
</Arguments>

## Examples

<Example caption="A scale off one colour, which is the usual reason to reach for this: five steps from a single value in the palette rather than five hex codes to keep in step with each other.">
```scss
$brand: #668f80;

.swatch--1 { background-color: $brand; }
.swatch--2 { background-color: shade($brand, 20%); }
.swatch--3 { background-color: shade($brand, 40%); }
.swatch--4 { background-color: shade($brand, 60%); }
.swatch--5 { background-color: shade($brand, 80%); }
```
```html
<style>
  :where(.scale) { display: flex; border-radius: 8px; overflow: hidden; }
  :where(.scale > div) { flex: 1; height: 88px; }
</style>
<div class="scale">
  <div class="swatch--1"></div>
  <div class="swatch--2"></div>
  <div class="swatch--3"></div>
  <div class="swatch--4"></div>
  <div class="swatch--5"></div>
</div>
```
</Example>

<Example caption="A darker hover state derived from the colour it darkens, so changing the brand colour changes both.">
```scss
$brand: #db504a;

.button {
  background-color: $brand;
}
.button:hover {
  background-color: shade($brand, 20%);
}
```
```html
<style>
  :where(.button) { border: 0; border-radius: 8px; padding: 12px 22px; color: #fff; font: 600 15px/1.4 Inter, ui-sans-serif, system-ui, sans-serif; cursor: pointer; }
</style>
<button class="button" type="button">Hover me</button>
```
</Example>

<Example caption="A colour from a modern space is mixed in that space and comes back in it, rather than being flattened to `rgb()`.">
```scss
.a { color: shade(oklch(0.52 0.12 160), 20%); }
.b { color: shade(lab(50% 20 -30), 20%); }
```
</Example>

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** A colour from a modern space used to stop the build with Sass's own `To use color.mix() with non-legacy color…`, although `isColor` had already accepted it. A legacy colour's result is unchanged to the last decimal place.

</Hint>

## What it refuses

**A length or any other unit in `$percentage`.** Until 4.0.0 `shade(red, 20px)` answered the same colour as `shade(red, 20%)`: the unit was thrown away and the number read as per cent, with only a Sass deprecation warning naming `$weight`, an argument this function does not have. Sass is removing that reading, so the call was on its way to breaking anyway.

```scss
.a {
  color: shade(red, 20px);
}
```
```text
Error: `20px` is not a valid $percentage for `shade`: `px` is not a proportion. Pass a percentage, such as `20%`.
```

**A percentage past either end of the mix**, which used to fail as `$weight: Expected 120% to be within 0% and 100%` and name neither the function nor its own argument.

```scss
.a {
  color: shade(red, 120%);
}
```
```text
Error: `120%` is not a valid $percentage for `shade`: it is outside 0% to 100%, and there is no colour past either end of the mix.
```

**Anything in `$color` that is not one colour.** `isColor` answers a list, because `isColor(red blue)` is a fair question, but `shade` mixes a single colour.

```scss
.a {
  color: shade(red blue, 20%);
}
```
```text
Error: `red blue` is not a single colour for `shade`. Pass one colour, such as `red` or `#bada55`.
```

A name that is not a colour is refused by `isColor` with its own message, and a `$percentage` that is not a number at all, such as `"20%"` in quotes, is refused too.
