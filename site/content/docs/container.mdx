# Container

<Member name="container">

A media query asks how wide the **viewport** is. That is the wrong question for a component that has to work in a sidebar, in a wide main column and in a grid cell on the same page. The **Container Sass mixin** marks an element as a query container, so [Container Query](/docs/container-query) can ask how wide **that element** is instead.

<Hint kind="danger">

**The rule that asks has to sit on a descendant.** An element is never matched by a `@container` rule that reads its own container, and one with no container ancestor matches nothing. Both fail silently: the rule is simply never applied.

</Hint>

</Member>

## Arguments

<Arguments of="container" footnote="Give the container a name when a component sits inside another container and you need to say which one you mean.">
  <Argument name="$name (null)" type="string">Accepts a container name as a string, such as <code>"card"</code>, or <code>null</code> for an unnamed container. Several names separated by spaces, <code>none</code>, a CSS-wide keyword and <code>var()</code> are written as they are. <code>and</code>, <code>or</code>, <code>not</code>, <code>default</code>, a name starting with a digit and a name holding a character such as <code>.</code> or <code>#</code> are refused, and so is <code>none</code> or a CSS-wide keyword beside another name: measured in Chrome 152, the browser dropped the whole declaration for each of them, even next to a valid name.</Argument>
  <Argument name="$type (inline-size)" type="string">Accepts <code>inline-size</code>, <code>size</code>, or <code>normal</code>. <code>inline-size</code> queries the width only, which is what almost every layout needs.</Argument>
</Arguments>

## Examples

<Example caption="**The card is the container, and it reads its own width.** One card, written once, dropped into three slots on the same page; the number beside each is how wide that copy is. The first is under 17rem, so it stacks. The second is over it and becomes a row. The third is over 26rem as well, so the description appears too. The window is one width for all three, which is exactly what a media query would have to go on.">
```scss
.card {
  @include container("card");
}

.card__body {
  @include container-query(min, 17rem, $name: "card") {
    display: flex;
    gap: 14px;
    align-items: center;
  }
}

.card__note {
  display: none;

  @include container-query(min, 26rem, $name: "card") {
    display: block;
  }
}
```

<Example caption="A named container. The name is what `container-query` targets when several containers are nested, and without one a query resolves to the nearest container ancestor, whichever that turns out to be.">
```scss
.card {
  @include container("card");
}

.panel {
  @include container;
}
```
</Example>

<Example caption="Querying height as well as width costs more, because the element then has to be sized independently of its content, which is what `size` asks for. Reach for it only when a query really needs the height.">
```scss
.panel {
  @include container(null, size);
}
```
</Example>

## What it refuses

Arguments are checked, so a wrong value stops the build with a message instead of quietly producing the wrong CSS.

```scss
.card {
  @include container("card", sideways);
}
```
```text
Error: `sideways` is not a valid $type for `container`. Pass one of: inline-size, size, normal.
```

```scss
.card {
  @include container(42);
}
```
```text
Error: `42` is not a valid $name for `container`. Pass a name as a string, such as `"card"`, or no name at all.
```

Since 4.0.0 a `$type` in quotes is written without them. `container-type: "size"` computes to `normal` in
Chrome 152, Firefox 156 and Safari 26.6.2, so the element was not a container
at all and no query on it ever matched. A name of nothing but spaces is
refused, because it wrote `container-name: ;`, which all three drop, leaving an
unnamed container and every `@container card` rule in the stylesheet quietly
matching nothing.

```scss
.card {
  @include container("  ");
}
```
```text
Error: `"  "` is not a valid $name for `container`: a name of nothing but spaces writes an empty `container-name`, which a browser drops, so the container ends up unnamed. Pass a name such as `"card"`, or no name at all.
```
