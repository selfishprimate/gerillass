# Breakpoint

<Member name="breakpoint">

The **Breakpoint** Sass mixin helps you create scalable media queries and breakpoints using the [@media CSS at-rule](https://developer.mozilla.org/en-US/docs/Web/CSS/@media) in SCSS.

<Hint kind="info">

**Tip:** There are predefined values for breakpoints in the `_map-for-breakpoints.scss` file based on Bootstrap's breakpoint values: `xsmall` at 0, `small` at 576px, `medium` at 768px, `large` at 992px, `xlarge` at 1200px and `xxl` at 1400px. **You can add more values here to expand the list or replace existing ones with yours**. `xxl` is new in Gerillass 4.0.0, where Bootstrap has had it since 2021.

</Hint>

</Member>

## Arguments

<Arguments of="breakpoint" footnote="When you use the `between` option you must pass two values for `width`, and they must be separated by a space. See the [examples](#examples) for more.">
  <Argument name="$mode" type="string">Sets the <code>width</code> media feature. Accepts the values <code>only</code>, <code>min</code>, <code>max</code>, and <code>between</code>.</Argument>
  <Argument name="$value" type="number (with unit)">The width value at which your styles will be applied: a key from the breakpoint map, or a length in any unit a width condition takes, such as <code>px</code>, <code>em</code>, <code>vw</code> or <code>cqi</code>, including <code>0</code> and <code>calc()</code>. A percentage, a bare number, another unit and a word that is not a key are refused, because the query they produce never matches. It cannot be a custom property either: <code>var()</code> is not evaluated in a <code>@media</code> condition, so the rule would never apply, and the mixin refuses it.</Argument>
</Arguments>

## Examples

<Hint kind="warning">

**One width on its own is a single pixel.** `breakpoint(320px)` compiles to `@media (width: 320px)`, so the styles apply only when the viewport is exactly 320px wide, and at every other width they do nothing. Since 2.2.0 the mixin prints a warning for that form. To style from a width upwards pass `min`, and for that exact width pass `only`.

</Hint>

<Example caption="Set the `$mode` option to `only` to apply styles at exactly one width. The code below will apply styles only if your browser's viewport is equal to `1200px`.">
```scss
.element{
  @include breakpoint(only, 1200px) {
    background-color: teal;
  };
}
```
</Example>

<Example caption="`min` applies the styles from a width upwards, which is the mobile-first direction, and a predefined name can stand in for the length.">
```scss
.element{
  @include breakpoint(min, medium) {
    background-color: green;
  };
}
```
</Example>

<Example caption="`max` applies them up to a width, for a desktop-first stylesheet. A custom length is used exactly as it is written.">
```scss
.element{
  @include breakpoint(max, 1024px) {
    background-color: green;
  };
}
```
</Example>

<Example caption="With a predefined value, `max` ends **just under** it, at `767.98px` for `medium`, so it hands over to `min, medium` without both applying at 768px.">
```scss
.element{
  @include breakpoint(max, medium) {
    flex-direction: column;
  };
  @include breakpoint(min, medium) {
    flex-direction: row;
  };
}
```
</Example>

<Hint kind="info">

**Tip:** You can use **predefined** and **custom** values together if you like.

</Hint>

<Example caption="Two values with `between` make a range, so the styles apply inside it and nowhere else.">
```scss
.element{
  @include breakpoint(between, small 1200px) {
    background-color: green;
  };
}
```
</Example>

<Hint kind="info">

**Important:** Please examine how the predefined breakpoint values line up against each other in the code below.

</Hint>

<Example caption="**Note that** a range ending at a predefined value ends **just under** it: 0.02px under in `px`, and 0.01 of a unit under in `rem` or `em`. **So neighbouring ranges neither overlap nor leave a gap between them.**">
```scss
.element{
  @include breakpoint(between, small medium) {
    background-color: green;
  };
  @include breakpoint(between, medium large) {
    background-color: blue;
  };
  @include breakpoint(between, large xlarge) {
    background-color: purple;
  };
}
```
</Example>

<Example caption="**Ending just under** only happens with **predefined** values. A custom value is used exactly as you write it, so end a range at the value you mean.">
```scss
.element{
  @include breakpoint(between, small 1199.98px) {
    background-color: green;
  };
  @include breakpoint(between, 1200px 1400px) {
    background-color: blue;
  };
}
```
</Example>

<Hint kind="warning">

**Why not one pixel under?** Until 4.0.0 a range ended 1 below a predefined value, `767px`, and `max` included the value itself, `768px`. Measured in Chrome 152, Firefox 156 and Safari 26.6.2: `max, medium` and `min, medium` both applied at exactly 768px in all three. Chrome and Firefox lay out fractional viewport widths, such as 767.5px in a frame or 767.27px with the display scaled to 110%, and there no range applied at all. With a map in `rem`, 1 under `48rem` is `47rem`, 16px short, and nothing applied from 752px to 768px. Ending 0.02px under, or 0.01rem under, left no overlap and no gap at any width measured. The CSS range syntax, `(width < 768px)`, measured as clean too, but Safari only supports it in media queries from 16.4 and drops the whole rule before that.

</Hint>

<Hint kind="info">

The values can be either custom numbers (with a unit) or predefined values.

</Hint>

<Example caption="Two values with no mode are the same range, since a pair can only mean one thing.">
```scss
.element{
  @include breakpoint(320px, 768px) {
    background-color: teal;
  };
}
```
</Example>

<Example caption="The same pair as predefined names.">
```scss
.element{
  @include breakpoint(small, large) {
    background-color: teal;
  };
}
```
</Example>

## What it refuses

A size no width condition can match stops the build. Until 2.3.1 these compiled: a name missing from the map went into the query as it was, so `breakpoint(min, huge)` wrote `@media (min-width: huge)`, which a browser keeps and never applies, with nothing to say so. Measured in Chrome 152, the same was true of a percentage, a bare number such as `768`, and a unit that is not a length.

```scss
.element {
  @include breakpoint(min, huge) {
    color: red;
  }
}
```
```text
Error: `huge` is not a breakpoint. $map-for-breakpoints has xsmall, small, medium, large, xlarge, xxl; pass one of those, or a length such as `600px`.
```

The names are case-sensitive, so `"MEDIUM"` is refused the same way.

```scss
.element {
  @include breakpoint(max, 50%) {
    color: red;
  }
}
```
```text
Error: `50%` cannot be used as a size in `breakpoint`: a width condition takes a length, and one written with `50%` would never match in @media. Pass a length such as `600px`, `40em` or `calc(30em + 1px)`, or a key from $map-for-breakpoints.
```

A length written as a string, `breakpoint(min, "600px")`, still works, as it always has.

A range has to be able to match, and two shapes cannot. Both compiled until
4.0.0, into valid CSS a browser keeps and no width ever satisfies, so the
styles inside simply never applied.

```scss
.element {
  @include breakpoint(large, small) { color: red; }
  @include breakpoint(medium, medium) { color: red; }
}
```
```text
Error: `large, small` is not a range `breakpoint` can match: it runs backwards, since 992px is wider than 576px. Pass the smaller size first.
Error: `medium, medium` is not a range `breakpoint` can match: both ends are the same width, and a range ends just before the key it names, so the query asks for at least 768px and under 768px at once.
```

A range of one width written by hand is a different thing and still works,
since a length ends at itself: `breakpoint(768px, 768px)` applies at exactly
768px, which is `only` written another way.
