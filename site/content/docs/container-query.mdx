# Container Query

<Member name="container-query">

The same component often has to work in a narrow sidebar and in a wide main column on the same page. A media query cannot tell those apart, because it only knows the viewport. The **Container Query Sass mixin** writes a `@container` rule, so the component responds to the width of its container instead.

It takes the same argument shapes as [Breakpoint](/docs/breakpoint), so the two read alike: a size, two sizes for a range, or `min`, `max`, `only` or `between` followed by a size. Sizes may be a key from `$map-for-breakpoints` or a raw length, and a raw length is the common case here, because a container is usually narrower than the viewport.

A size on its own matches that exact width and no other, `(width: 400px)`, which is a single pixel. The mixin prints a warning for it since 2.2.0. Write `only` when that is what you mean.

<Hint kind="danger">

**Put the container on an ancestor of the element you are styling.** This is the one thing to get right, and nothing tells you when you get it wrong: an element is never matched by a `@container` rule that reads its own container, and one with no container ancestor matches nothing. The rule is simply never applied.

</Hint>

</Member>

## Arguments

<Arguments of="container-query" footnote="$name is passed as a keyword rather than by position, because `container-query(&quot;card&quot;, &quot;medium&quot;)` could not be told apart from `container-query(&quot;min&quot;, &quot;medium&quot;)`.">
  <Argument name="$params…" type="string, number">Accepts a size, which matches that exact width only and prints a warning, two sizes for a range, or one of <code>min</code>, <code>max</code>, <code>only</code> or <code>between</code> followed by a size. A size cannot be a custom property: <code>var()</code> is not evaluated in a <code>@container</code> condition, so the rule would never apply, and the mixin refuses it.</Argument>
  <Argument name="$name" type="string">Accepts a container name as a string, to query one named container rather than the nearest one. Pass it as a keyword, <code>$name: "card"</code>. It has to be one name a browser keeps in an <code>@container</code> rule, so <code>var()</code>, <code>none</code>, <code>and</code>, <code>or</code>, <code>not</code>, <code>default</code>, a CSS-wide keyword, a name with a space and a name starting with a digit are refused. Measured in Chrome 152, each of them dropped the rule, and <code>not</code> turned the query into its opposite.</Argument>
</Arguments>

## Examples

<Example resizable hint="Drag the box: the panel is the container, and the component inside it changes twice on the way in." caption="**`container` marks the box, `container-query` asks about it.** The panel carries the container and the media object inside it reads it, at 20rem and again at 30rem. Nothing here knows the window's width; every rule is answering the panel.">
```scss
.panel {
  @include container("panel");
}

.media {
  @include container-query(min, 20rem, $name: "panel") {
    display: flex;
    gap: 16px;
    align-items: center;
  }
}

.media img {
  @include container-query(min, 20rem, $name: "panel") {
    flex: none;
    width: 110px;
    aspect-ratio: 1;
  }
}

.media__note {
  display: none;

  @include container-query(min, 30rem, $name: "panel") {
    display: block;
  }
}
```

<Example caption="From a width upwards, which is the one you will reach for most.">
```scss
.title {
  @include container-query("min", 400px) {
    font-size: 2rem;
  }
}
```
</Example>

<Example caption="Up to a width.">
```scss
.title {
  @include container-query("max", 399px) {
    font-size: 1rem;
  }
}
```
</Example>

<Example caption="A range, written either with `between` or as two sizes. Both produce the same rule.">
```scss
.title {
  @include container-query("between", 300px 500px) {
    color: red;
  }
}
.title {
  @include container-query(300px, 500px) {
    color: red;
  }
}
```
</Example>

<Example caption="A predefined breakpoint name works too, resolved through `$map-for-breakpoints`.">
```scss
.title {
  @include container-query("min", "medium") {
    color: red;
  }
}
```
</Example>

<Example caption="A range or a `max` that ends at a predefined name ends **before** it, written as `width <`, so a range that starts at the same name takes over without both applying. A length you write yourself is used as written.">
```scss
.title {
  @include container-query("small", "medium") {
    font-size: 1.25rem;
  }
  @include container-query("medium", "large") {
    font-size: 1.5rem;
  }
}
```
</Example>

<Hint kind="info">

**Why `width <` rather than a smaller number.** A range used to end on the name, so both neighbouring ranges applied to a container exactly that wide. Container widths are usually fractional -- Firefox lays them out in 1/60px and Safari in 1/64px -- and a `.98` end left those widths in no range at all, where `width <` leaves neither a gap nor an overlap. Range syntax works in `@container` in every browser that has container queries.

</Hint>

<Example caption="Naming the container you mean. Without a name the query resolves to the nearest container ancestor, which is the wrong one as soon as containers are nested.">
```scss
.title {
  @include container-query("min", 400px, $name: "card") {
    color: red;
  }
}
```
</Example>

## What it refuses

Arguments are checked, so a wrong value stops the build with a message instead of quietly producing the wrong CSS.

```scss
.title {
  @include container-query("min", 400px, 800px) {
    color: red;
  }
}
```
```text
Error: `container-query` takes one or two arguments, and was given 3. Pass a size, two sizes for a range, or one of `min`, `max`, `only` or `between` followed by a size.
```

```scss
.title {
  @include container-query("min", 400px, $name: 42) {
    color: red;
  }
}
```
```text
Error: `42` is not a valid $name for `container-query`. Pass a container name as a string, such as `"card"`.
```

A size no width condition can match is refused, as it is in [Breakpoint](/docs/breakpoint): a name missing from the map, a percentage, a bare number, or a unit that is not a length. Each used to compile into an `@container` rule that never applies. Container units such as `cqi` are lengths and are accepted.

```scss
.title {
  @include container-query("min", 50%) {
    color: red;
  }
}
```
```text
Error: `50%` cannot be used as a size in `container-query`: a width condition takes a length, and one written with `50%` would never match in @container. Pass a length such as `600px`, `40em` or `calc(30em + 1px)`, or a key from $map-for-breakpoints.
```

A name from a custom property is refused too. The query needs the name itself, even where the container takes its name from `var()`, which the [Container](/docs/container) mixin allows.

```scss
.title {
  @include container-query("min", 400px, $name: var(--container)) {
    color: red;
  }
}
```
```text
Error: `var(--container)` is not a valid $name for `container-query`: a custom property is not evaluated in a @container condition, so the rule would never apply. Pass the name itself, such as `"card"`; the `container` mixin can still take its name from a custom property.
```

A range has to be able to match, and two shapes cannot. Both compiled until
4.0.0, into valid CSS a browser keeps and no width ever satisfies, so the
styles inside simply never applied.

```scss
.element {
  @include container-query(large, small) { color: red; }
  @include container-query(medium, medium) { color: red; }
}
```
```text
Error: `large, small` is not a range `container-query` can match: it runs backwards, since 992px is wider than 576px. Pass the smaller size first.
Error: `medium, medium` is not a range `container-query` can match: both ends are the same width, and a range ends just before the key it names, so the query asks for at least 768px and under 768px at once.
```

A range of one width written by hand is a different thing and still works,
since a length ends at itself: `container-query(768px, 768px)` applies at exactly
768px, which is `only` written another way.
