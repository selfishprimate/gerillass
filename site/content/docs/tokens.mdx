# Tokens

<Member name="tokens">

The **Tokens Sass mixin** writes a Sass map out as CSS custom properties, for any kind of token: colours, spacing, sizes, radii, type, shadows and durations. Keep each scale as a map and emit it once, with a prefix if you want one: `(4: 1rem)` with the prefix `space` becomes `--space-4: 1rem`.

A loop over the map does the same in three lines, and gets three things wrong without a sound. The mixin handles each of them.

</Member>

## Arguments

<Arguments of="tokens" footnote="The mixin writes into the rule it is called in, so call it inside a selector: `:root` for values the whole page shares, or a theme selector to override some of them.">
  <Argument name="$map" type="map">The names and values. A name can be a word or a number, such as <code>bg</code> or <code>500</code>, using letters, digits, hyphens and underscores, and without the leading <code>--</code>, which the mixin writes itself. A value can be anything CSS accepts: a colour, a length, a font stack, a shadow, a duration, <code>calc()</code> or <code>clamp()</code>, and <code>var()</code> pointing at another token. A value of <code>null</code> is left out; an empty one is refused. A nested map is refused.</Argument>
  <Argument name="$prefix (null)" type="string">Joined to each name with a hyphen. <code>color</code> turns <code>bg</code> into <code>--color-bg</code>. The mixin writes that hyphen, so a prefix with one at either end is refused.</Argument>
</Arguments>

## Examples

<Example caption="A map goes in and custom properties come out, one per entry, with the prefix joined on by a hyphen. This is the whole of what the mixin does; everything below is a consequence of it.">
```scss
:root {
  @include tokens((sm: 4px, md: 8px, lg: 16px), radius);
}

.tile {
  border-radius: var(--radius-lg);
}
```
```html
<style>
  .tile { width: 120px; height: 72px; background: #668f80; }
</style>
<div class="tile"></div>
```
</Example>

<Example caption="A value of `null` leaves the property out, which is not the same as writing it. The middle chip asks for a token the map set to `null`, so its `var()` falls back to the terra; the third asks for one written `--color-loop: null` by hand, the way a loop would, and falls back to nothing at all, because `null` is a value." listing="<span class=&quot;chip chip--set&quot;>set</span>
<span class=&quot;chip chip--skipped&quot;>null, left out</span>
<span class=&quot;chip chip--loop&quot;>a loop&#39;s null</span>">
```scss
:root {
  @include tokens((brand: #668f80, accent: null), color);

.chip--set     { background: var(--color-brand, #db504a); }
.chip--skipped { background: var(--color-accent, #db504a); }

```


## What goes wrong in a loop

Measured in Chrome 152, with `#{$name}: #{$value}` in an `@each` loop:

| In the map | What the loop writes | What happens in the browser |
|---|---|---|
| `arrow: "→"` | `--arrow: →` | the quotes are gone, and `content: var(--arrow)` computes to `none` |
| `focus: null` | `--focus: null` | `null` is a value, so `var(--focus, red)` never falls back to red |
| `space-0.5: 2px` | `--space-0.5: 2px` | the declaration is dropped; so are names holding `/`, a space or `#` |

The mixin keeps the quotes, leaves a `null` out, and refuses a name the browser would drop, saying which character is the problem.

The first two only happen when the values come from Sass: written as plain CSS, a quoted string stays quoted and there is no `null` to write. The third happens either way, and a hand-written `--space-0.5` is dropped just the same.

## When to use it

If the values are a fixed list that nothing else reads, write them as CSS. `:root { --space-4: 1rem; }` is shorter than a map and an include, and this mixin adds nothing to it.

It earns its place when the values already live in Sass for another reason:

- **The same value has to reach somewhere a custom property cannot.** A `@media` condition does not evaluate `var()`: measured in Chrome 152, `(min-width: var(--wide))` did not match even with `--wide` set. Keep the widths in one map, and the custom properties and the media queries come from the same place, so changing one changes both.
- **One theme is derived from another.** With `map.merge`, the dark map is the light one with the colours that differ replaced, so the ones it shares cannot drift apart.
- **Other Sass reads the same values.** A scale worked out with `math`, or a map another mixin takes as well, is already a map. Writing it out again as CSS would be a second copy to keep in step.

<Example caption="One map of widths feeds both the custom properties and the media queries, and the dark theme is the light one with two colours changed. The dark rule repeats the border it did not change, which is harmless.">
```scss
@use "sass:map";
@use "gerillass" as *;

$screens: (md: 768px, lg: 1024px);
$light: (bg: #fafaf8, text: #222c25, border: #f2f2eb);
$dark: map.merge($light, (bg: #222c25, text: #fafaf8));

:root {
  @include tokens($screens, screen);
  @include tokens($light, color);
}

[data-theme="dark"] {
  @include tokens($dark, color);
}

@each $name, $width in $screens {
  @media (min-width: $width) {
    .container {
      max-width: $width;
    }
  }
}
```
</Example>

## What it refuses

A name the browser would drop, and a nested map, stop the build instead of compiling into CSS that does nothing.

```scss
:root {
  @include tokens(("space-0.5": 2px), space);
}
```
```text
Error: `space-0.5` is not a valid token name for `tokens`: a custom property name cannot contain `.`. Use letters, digits, hyphens and underscores, such as `space-0_5`.
```

```scss
:root {
  @include tokens((blue: (500: #668f80)), color);
}
```
```text
Error: `blue` holds a map, which `tokens` does not flatten. Pass each group on its own, such as `@include tokens($blue, blue)` for `$blue: (500: #3b82f6)`.
```

The mixin writes the `--` itself, and the hyphen after a prefix, so a name or a prefix that brings its own doubles them. `(--bg: #fff)` wrote `----bg` and `$prefix: color-` wrote `--color--bg`: real properties in all three engines, holding the value under a name nothing in the stylesheet asks for. Measured in Chrome 152, Firefox 156 and Safari 26.6.2, `----bg` computed to its value while `--bg`, which is what the author would write in `var()`, computed to the empty string.

```scss
:root {
  @include tokens((--bg: #fff));
}
```
```text
Error: `--bg` is not a valid token name for `tokens`: the mixin writes the `--` itself, so this would become `----bg`. Drop the leading hyphens and pass `bg`.
```

```scss
:root {
  @include tokens((bg: #fff), "color-");
}
```
```text
Error: `color-` is not a valid $prefix for `tokens`: the mixin writes the `--` and the hyphen before the name, so a prefix that starts or ends with one doubles it. Pass `color`.
```

An empty value is the same trap as `null`, one line further on: a custom property may hold nothing, and `var()` does not fall back for it. Measured in all three, `--empty: ;` computed to the empty string and `var(--empty, red)` stayed at the initial value. A quoted `""` is a real string a `content` can use and is written as it is.

```scss
@use "sass:string";
@use "gerillass" as *;

:root {
  @include tokens((label: string.unquote("")));
}
```
```text
Error: `label` has an empty value in `tokens`. A custom property holding nothing is not the same as one that is not set: `var(--label, red)` does not fall back. Pass a value, `""` for an empty string, or null to leave the property out.
```
