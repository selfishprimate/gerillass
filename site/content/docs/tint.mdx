# Tint

<Member name="tint">

Mixes a colour towards white by a percentage.

</Member>

## Arguments

<Arguments of="tint">
  <Argument name="$color" type="color">Accepts a colour.</Argument>
  <Argument name="$percentage" type="number (percentage)">Accepts a percentage.</Argument>
</Arguments>

## Examples

<Example caption="A pale background derived from the same brand colour.">
```scss
$brand: crimson;
.notice {
  border: 1px solid $brand;
  background-color: tint($brand, 80%);
}
```
</Example>

## What it refuses

Arguments are checked, so a wrong value stops the build with a message instead of quietly producing the wrong CSS.

```scss
$brand: crimson;
.notice {
  background-color: tint(brand, 85%);
}
```
```text
Error: 'brand' is not a color value, please replace it with a valid one.
```

<Hint kind="info">

**One colour, not a list.** `isColor` answers a list, because `isColor(red blue)` is a fair question, and `tint` mixes a single colour. Until 4.0.0 a list walked past the guard and ended the build with Sass's own message, which names neither the function nor the argument.

```scss
.a {
  color: tint(red blue, 20%);
}
```
```text
Error: `red blue` is not a single colour for `tint`. Pass one colour, such as `red` or `#bada55`.
```

</Hint>
