# Reveal

<Member name="reveal">

The **Reveal** Sass mixin animates something in and out of the page: a popover, a `<dialog>`, or a plain element a class shows and hides. It writes the pieces that make a `display: none` transition work, and each of those pieces does nothing on its own.

</Member>

<Hint kind="warning">

**New in Gerillass 4.0.0.**

</Hint>

## Why this needs a mixin

`display: none` could not be transitioned, which is why fading a menu in was a JavaScript job for years. CSS can do it now, and it takes three things that have to agree. Measured in Chrome 152, Firefox 156 and Safari 26.6.2, on a popover, a modal dialog and a class-toggled element, reading the computed opacity 80ms into each direction:

| What is written | On the way in | On the way out |
|---|---|---|
| all of it | animates in all three | Chrome and Safari |
| without `@starting-style` | **nothing, in any browser** | animates |
| without `allow-discrete` on `display` | animates | **nothing, in any browser** |

Neither failure says anything. The CSS is valid, the transition is there, and half the effect is missing. Both are in the repository's lab as demos you can click, beside the mixin on the same three shapes.

`@starting-style` also has to come **after** the rule it starts from. Written before it, it does nothing, and again without a word.

<Hint kind="danger">

**Firefox does not run the exit.** Measured in Firefox 156 on all three shapes: the element animates in and then disappears at once, although the browser answers `true` for `CSS.supports("transition-behavior", "allow-discrete")`. Chrome 152 and Safari 26.6.2 animate both ways. What a Firefox user gets is the entry animation and an instant close, which is a smaller effect rather than a broken one.

</Hint>

## Arguments

<Arguments of="reveal" footnote="The mixin goes on the element that is shown and hidden, not on the button that toggles it.">
  <Argument name="$open" type="string"><code>popover</code>, the default, writes the open state as <code>:popover-open</code>; <code>dialog</code> writes <code>[open]</code>; a string such as <code>".is-open"</code> is the selector your own code adds. It is attached to the element with no combinator, so it has to start with <code>.</code>, <code>#</code>, <code>[</code> or <code>:</code>.</Argument>
  <Argument name="$duration" type="number">One time, <code>0.3s</code> by default. It is written into every part of the transition, the discrete ones included.</Argument>
  <Argument name="$move" type="list">Where it comes from: a direction, <code>top</code>, <code>bottom</code>, <code>left</code> or <code>right</code>, with an optional distance, as in <code>top 0.75rem</code>. <code>none</code> fades without moving.</Argument>
  <Argument name="$scale" type="number">A unitless number above zero, such as <code>0.95</code>, to grow into place. Left out, the size is not touched.</Argument>
  <Argument name="$backdrop" type="boolean"><code>true</code> by default, which writes the same three pieces again for <code>::backdrop</code>, since a dialog's backdrop is a second element with its own transition. <code>false</code> leaves it alone.</Argument>
  <Argument name="$easing" type="string">Any easing a transition takes, <code>ease</code> by default.</Argument>
</Arguments>

</Example>

## What it writes

```scss
.tooltip {
  @include reveal;
}
```

```css
.tooltip {
  opacity: 0;
  translate: 0 -0.75rem;
  transition: opacity 0.3s ease, translate 0.3s ease, display 0.3s allow-discrete, overlay 0.3s allow-discrete;
}
.tooltip:popover-open {
  opacity: 1;
  translate: 0 0;
}
@starting-style {
  .tooltip:popover-open {
    opacity: 0;
    translate: 0 -0.75rem;
  }
}
.tooltip::backdrop {
  opacity: 0;
  transition: opacity 0.3s ease, display 0.3s allow-discrete, overlay 0.3s allow-discrete;
}
.tooltip:popover-open::backdrop {
  opacity: 1;
}
@starting-style {
  .tooltip:popover-open::backdrop {
    opacity: 0;
  }
}
@media (prefers-reduced-motion: reduce) {
  .tooltip, .tooltip::backdrop {
    transition-duration: 0.01ms;
  }
}
```

The closed state is the base rule, so an element that is never opened is already in it. `overlay` is in the transition for the top layer, and it is Chrome's property alone: Firefox and Safari do not support it and ignore the line. What it buys was measured in Chrome 152, 100ms into a close: with the line the popover computes `overlay: auto` and without it `overlay: none`, so the one without has already left the top layer while it is still fading, and is painted among the page's own content instead of above it.

<Hint kind="info">

**Reduced motion shortens the transition rather than removing it.** `transition: none` would take the discrete part with it, and then the element never leaves the page. `0.01ms` is a cut: measured in Chrome 152 and Firefox 156 with the preference set, the element appears and disappears at once, with no motion and nothing left behind. Safari cannot be put into reduced motion from automation, so it was not measured there.

</Hint>

## Several on one page

They do not touch each other. The mixin writes no shared keyframes and needs no call at the root of your stylesheet, which `loadify` does, so every include is a rule of its own with its own duration and its own direction.

Measured in Chrome 152, Firefox 156 and Safari 26.6.2, with five of them on one page at durations from 0.2s to 0.6s: two opened at the same moment were each at their own point of their own animation 100ms in, 0.16 and 0.22 of the way, and opening or closing any one of them left the others exactly as they were.

<Hint kind="info">

**What does close another is HTML, not this mixin.** A `popover` closes any other `popover` that is open, and `showModal()` closes them all. That is the popover API's own behaviour and it happens with or without this mixin; what the mixin adds is that the one being closed animates out properly. If two should be open at once, write `popover="manual"` on them: in the same measurement the manual one stayed open through every other one opening and closing.

</Hint>

## What it refuses

```scss
.a {
  @include reveal(nonsense);
  @include reveal(popover, 0.3s, sideways);
  @include reveal(popover, 0.3s, top -1rem);
  @include reveal(popover, 0.3s, top, 0);
}
```
```text
Error: `nonsense` is not a valid $open for `reveal`. Pass `popover`, `dialog`, or the selector your own code adds to the element, starting with `.`, `#`, `[` or `:`, such as `".is-open"`.
Error: `sideways` is not a valid direction for `reveal`. Pass `none`, or one of: top, bottom, left, right, with an optional distance such as `top 1rem`.
Error: `-1rem` is not a valid distance for `reveal`: a length below zero does not work here. It is written into `translate`, and a browser drops the declaration.
Error: `0` is not a valid $scale for `reveal`. Pass a unitless number above zero, such as `0.95`, or nothing to leave the size alone.
```

A bare word for `$open` is the one worth explaining: the state is attached to the element with no combinator, so `reveal(nonsense)` would have compiled into `.aNonsense`, a selector that matches nothing and says nothing.
