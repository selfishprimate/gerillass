# Reveal

<Member name="reveal">

The **Reveal** Sass mixin animates something in and out of the page: a popover, a `<dialog>`, or a plain element a class shows and hides. It writes the pieces that make a `display: none` transition work, and each of those pieces does nothing on its own.

</Member>

<Hint kind="warning">

**New in Gerillass 4.0.0.** An entry and exit animation is three pieces, and two of them fail silently on their own: without `@starting-style` the element appears at its final state with nothing to animate from, and without `transition-behavior: allow-discrete` the exit is skipped because `display` and `overlay` are discrete properties. The mixin writes all three, for a popover, a dialog and a class-toggled element alike.

</Hint>

<Hint kind="danger">

**Firefox does not run the exit.** Measured in Firefox 156 on all three shapes: the element animates in and then disappears at once, although the browser answers `true` for `CSS.supports("transition-behavior", "allow-discrete")`. Chrome 152 and Safari 26.6.2 animate both ways. What a Firefox user gets is the entry animation and an instant close, which is a smaller effect rather than a broken one.

</Hint>

## Arguments

<Arguments of="reveal" footnote="The mixin goes on the element that is shown and hidden, not on the button that toggles it.">
  <Argument name="$open" type="string"><code>popover</code>, the default, writes the open state as <code>:popover-open</code>; <code>dialog</code> writes <code>[open]</code>; a string such as <code>".is-open"</code> is the selector your own code adds. It is attached to the element with no combinator, so it has to start with <code>.</code>, <code>#</code>, <code>[</code> or <code>:</code>.</Argument>
  <Argument name="$duration" type="number">One time, <code>0.3s</code> by default. It is written into every part of the transition, the discrete ones included.</Argument>
  <Argument name="$move" type="list">Where it comes from: a direction, <code>top</code>, <code>bottom</code>, <code>left</code> or <code>right</code>, with an optional distance, as in <code>top 0.75rem</code>. <code>none</code> fades without moving.</Argument>
  <Argument name="$scale" type="number">A unitless number above zero, such as <code>0.95</code>, to grow into place. Left out, the size is not touched.</Argument>
  <Argument name="$backdrop" type="boolean"><code>true</code> by default, which writes the same three pieces again for <code>::backdrop</code>, since a dialog's backdrop is a second element with its own transition. <code>false</code> leaves it alone.</Argument>
  <Argument name="$easing" type="string">Any easing a transition takes, <code>ease</code> by default: one of the seven keywords in any case, <code>cubic-bezier()</code>, <code>steps()</code>, <code>linear()</code> or a <code>var()</code>. Anything else is refused, because the easing is one part of a <code>transition</code> and a value that is not a timing function drops the whole declaration. <code>null</code> leaves the slot empty, which all three browsers parse.</Argument>
</Arguments>

<Hint kind="danger">

**Do not set `display` on a popover this is on.** An author's `display` beats the rule a browser hides a closed popover with, so the element never leaves: it stays invisible on the page and still takes clicks. Lay its contents out on a child instead, as the menu above does.

</Hint>

## A dialog, and your own selector

Only the popover is on this page. The other two shapes open with a line of script and these frames run none, measured on 21 September 2026: a demo's own script is blocked both by the frame's sandbox and by the site's `script-src`, and a `:target` link, the one other way to change state without script, navigates the srcdoc document and replaces it. So both are written out here, and the repository's own lab, which does run scripts, has all three side by side.

A `<dialog>` opened with `showModal()`. `dialog` writes the open state as `[open]`, which the browser adds and removes itself, and `$backdrop` is left at its default, so the layer behind the dialog fades with it rather than appearing and vanishing on its own:

```scss
.modal {
  @include reveal(dialog, 0.45s, none, 0.9);
}
```

An element your own code shows and hides with a class. The mixin writes the same three pieces against whatever selector you name, and the `display` pair is yours:

```scss
.menu {
  display: none;

  @include reveal(".is-open", 200ms, right 1rem, null, false);
}

.menu.is-open {
  display: block;
}
```

## Several on one page

They do not touch each other. The mixin writes no shared keyframes and needs no call at the root of your stylesheet, which `loadify` does, so every include is a rule of its own with its own duration and its own direction.

Measured in Chrome 152, Firefox 156 and Safari 26.6.2, with five of them on one page at durations from 0.2s to 0.6s: two opened at the same moment were each at their own point of their own animation 100ms in, 0.16 and 0.22 of the way, and opening or closing any one of them left the others exactly as they were.

<Hint kind="info">

**What closes one popover is HTML, not this mixin.** A `popover` closes any other that is open, and `showModal()` closes them all; what the mixin adds is that the one being closed animates out properly. If two should be open at once, write `popover="manual"` on them.

</Hint>

## What it refuses

```scss
.a {
  @include reveal(nonsense);
  @include reveal(popover, 0.3s, sideways);
  @include reveal(popover, 0.3s, top -1rem);
  @include reveal(popover, 0.3s, top, 0);
}
```
```text
Error: `nonsense` is not a valid $open for `reveal`. Pass `popover`, `dialog`, or the selector your own code adds to the element, starting with `.`, `#`, `[` or `:`, such as `".is-open"`.
Error: `sideways` is not a valid direction for `reveal`. Pass `none`, or one of: top, bottom, left, right, with an optional distance such as `top 1rem`.
Error: `-1rem` is not a valid distance for `reveal`: a length below zero does not work here. It is written into `translate`, and a browser drops the declaration.
Error: `0` is not a valid $scale for `reveal`. Pass a unitless number above zero, such as `0.95`, or nothing to leave the size alone.
```

A bare word for `$open` is the one worth explaining: the state is attached to the element with no combinator, so `reveal(nonsense)` would have compiled into `.aNonsense`, a selector that matches nothing and says nothing.

An easing the browser cannot read is the quietest of these, because it takes
more with it than itself. The value is one component of a `transition`, so a
browser that cannot read it drops the whole declaration, `allow-discrete`
included, and the element then neither animates nor leaves the top layer.
Measured in Chrome 152, Firefox 156 and Safari 26.6.2, all three the same: with
`nonsense`, `10px` or a colour in that slot the computed transition came back as
`all / 0s / normal`, and so it did for `inherit` and the other CSS-wide
keywords, which only work as a whole declaration rather than as one part of one.

```scss
.element {
  @include reveal(popover, 0.3s, top 1rem, null, true, nonsense);
}
```
```text
Error: `nonsense` is not a valid $easing for `reveal`: it is not one of: linear, ease, ease-in, ease-out, ease-in-out, step-start, step-end. It is written into a `transition`, where a value that is not a timing function drops the whole declaration, so nothing animates and the element does not leave the top layer. Pass a keyword, `cubic-bezier()`, `steps()`, `linear()` or a `var()`.
```

The mixin writes the closed state as declarations and the open state as the
element plus its state selector, so it needs a rule to hang both on.

```scss
@include reveal;
```
```text
Error: `reveal` animates the element it is called in, so call it inside a selector, such as `.panel { @include reveal; }`.
```
