# Triangle

<Member name="triangle">

The **Triangle** Sass mixin helps you generate triangles using the `::before` or `::after` CSS pseudo-elements.
<Hint kind="info">

**Tip:** It works best with text based elements, where it points in a direction to invite the user to take action (for example, dropdown menu labels). It is especially useful when you apply it to the selected element's `::before` or `::after` pseudo-elements.

</Hint>

</Member>

## Arguments

<Arguments of="triangle" footnote="When you pass `top`, `right`, `bottom`, `left` or one of the four logical directions for the **`$direction`** argument, you can pass two values to resize the triangle. **The first value controls the width of the triangle and the second controls the height.**">
  <Argument name="$direction" type="string">Sets the direction of the triangle. Accepts the values <code>top</code>, <code>top-right</code>, <code>right</code>, <code>bottom-right</code>, <code>bottom</code>, <code>bottom-left</code>, <code>left</code>, and <code>top-left</code>. The logical directions <code>inline-start</code>, <code>inline-end</code>, <code>block-start</code> and <code>block-end</code> follow the writing direction instead: <code>inline-end</code> points right on a left-to-right page and left on a right-to-left one.</Argument>
  <Argument name="$color" type="color, keyword, function">The color of the triangle. Accepts a Sass color, <code>currentColor</code>, a system color such as <code>Canvas</code>, or a function the browser resolves to a color, such as <code>var()</code>, <code>color-mix()</code>, <code>light-dark()</code>, <code>contrast-color()</code> or <code>rgb(from ...)</code>. Until 2.3.1 only four functions were accepted, and a system color or <code>contrast-color()</code> was refused, although a border keeps both. <code>inherit</code>, <code>initial</code>, <code>unset</code> and <code>revert</code> are refused, because the color is written into a <code>border-color</code> shorthand beside <code>transparent</code>, where a browser rejects them.</Argument>
  <Argument name="$size" type="number (with unit), function">The size of the triangle. Multiple values must be separated by a space. Each value can also be <code>var()</code>, <code>env()</code>, or a calculation such as <code>calc()</code> or <code>clamp()</code>. Not a percentage or a negative length, which <code>border-width</code> drops.</Argument>
</Arguments>

## Examples

<Example caption="Suppose you have an expandable box and you want users to click a label to expand it. **Let's apply the mixin to the `::after` pseudo-element of the selected element.**" listing="<div class=&quot;element&quot;>Click here to expand it!</div>">
```scss
.element {
  &::after {
    @include triangle;
  }
}
```

</Example>

<Example caption="Now let's **change the `$color` and the `$size`** of the triangle, and separate it from the text by **passing a declaration block into the mixin**.">
```scss
.element {
  &::after {
    @include triangle(
      $color: crimson,
      $size: 6px
    ) {
      margin-left: 6px;
    };
  }
}
```
```html
<div class="element example02">Click here to expand it!</div>
```
</Example>

<Example caption="When you pass one of the `top`, `right`, `bottom`, or `left` values for the `$direction` argument, you can pass a second value to resize the triangle. The first value controls the width of the triangle and the second controls the height.">
```scss
.element{
  &::after {
    @include triangle(
      $direction: "bottom",
      $color: crimson,
      $size: 10px 6px
    ) {
      position: relative;
      margin-left: 6px;
      top: -2px;
    };
  }
}
```
```html
<div class="element example03">Click here to expand it!</div>
```
</Example>

<Example caption="You can apply the mixin not only to the pseudo-elements, but to the selected element itself.">
```scss
.element{
  @include triangle(
    $direction: "top",
    $color: crimson,
    $size: 100px 50px
  )
}
```
```html
<div class="element example04"></div>
```
</Example>

<Example caption="**Logical directions** follow the writing direction. `inline-end` points to where a line ends: right in a left-to-right sentence, left in a right-to-left one, from the same rule. Measured in Chrome 152, each logical direction renders the same borders as its physical twin in both directions.">
```scss
.next::after {
  @include triangle("inline-end", currentColor, 8px 12px);
  margin-inline-start: 8px;
}
```

## What it refuses

A size the browser drops stops the build. The sizes are written into `border-width`, which in Chrome 152 drops a percentage and a negative width, so the triangle is not drawn. Until 2.3.1 both compiled; a word or a unitless number was already refused.

```scss
.caret {
  @include triangle("top", red, 5%);
}
```
```text
Error: `5%` is not a valid $size for `triangle`: a percentage does not work here. A browser drops the border widths, so no triangle is drawn.
```
