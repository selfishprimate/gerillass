# Aspect Ratio

<Member name="aspect-ratio">

The **Aspect Ratio Sass mixin** holds an element to the ratio you give it. CSS
has an `aspect-ratio` property of its own, and this mixin adds the four things
that property leaves out.

</Member>

<Hint kind="warning">

**New in Gerillass 2.0.0.** This mixin replaces **Ratio Box** and **Responsive
Video**, which were byte-identical to each other and are both gone. It goes on
**the element itself**, not on a wrapper around it. See [Coming from Ratio Box
or Responsive Video](#coming-from-ratio-box-or-responsive-video).

</Hint>

<Hint kind="info">

**Why the extra declarations?** A ratio on its own stretches an `<img>` rather than cropping it, and an `<iframe>` overflows its container by its 2px default border, so the mixin writes `object-fit` and `border: 0`. A `height` attribute, which images and embed codes usually carry, beats the ratio outright, so it writes `height: auto` too, in a way that a height you set yourself still wins. See [Images and embeds with a height
attribute](#images-and-embeds-with-a-height-attribute).

</Hint>

## Arguments

<Arguments of="aspect-ratio" footnote="Pass null as the second argument to leave object-fit out of the output entirely.">
  <Argument name="$ratio (16/9)" type="string, number, function">
    The ratio to hold. Accepts a slash separated string such as <code>16/9</code>, a colon separated string such as <code>16:9</code>, a bare number, where <code>1.5</code> means 1.5 to 1, or <code>var()</code>, which is written as it is. The default is <code>16/9</code>. Anything else is refused with an error.
  </Argument>
  <Argument name="$fit (cover)" type="string">
    Sets the <code>object-fit</code> property. Accepts <code>fill</code>, <code>contain</code>, <code>cover</code>, <code>none</code>, <code>scale-down</code>, or <code>null</code> to leave <code>object-fit</code> alone. The default is <code>cover</code>.
  </Argument>
</Arguments>

## Examples

<Example title="No arguments" caption="Call it without arguments and the ratio is 16/9.">
```scss
.element {
  @include aspect-ratio;
}
```
</Example>

<Example
  title="On an image"
  caption="Because object-fit defaults to cover, the image is cropped to fill the box rather than stretched."
>
```scss
.element {
  @include aspect-ratio("16:9");
}
```
```html
<img class="element" src="/images/landscape.webp" alt="A 16 by 9 box holding a cropped photograph" />
```
</Example>

<Example
  title="A different ratio"
  caption="A colon and a slash mean the same thing, so 16:9 and 16/9 give identical output."
>
```scss
.element {
  @include aspect-ratio("4/3");
}
```
```html
<img class="element" src="/images/landscape.webp" alt="A 4 by 3 box holding a cropped photograph" />
```
</Example>

<Example
  title="Containing instead of cropping"
  caption="Pass a second value to change how the content fills the box. Here the box is square and the whole image stays visible."
>
```scss
.element {
  @include aspect-ratio("1:1", contain);
  background: #f2f2eb;
}
```
```html
<img class="element" src="/images/landscape.webp" alt="A square box containing the whole photograph" />
```
</Example>

<Example
  title="A bare number, and no object-fit"
  caption="1.5 means 1.5 to 1. Passing null as the second argument leaves object-fit out, which is what you want when the element has no content of its own to fit."
>
```scss
.element {
  @include aspect-ratio(1.5, null);
}
```
</Example>

<Example
  title="An embedded video"
  caption="Apply the mixin to the iframe itself, and paste the embed code as it comes, `width` and `height` attributes included. There is no wrapper element and no padding hack."
  listing="<iframe class=&quot;element&quot; width=&quot;560&quot; height=&quot;315&quot; src=&quot;https://www.youtube.com/embed/JBc6JiRlsOU&quot; title=&quot;YouTube video player&quot; allowfullscreen></iframe>"
  interactive
  height={420}
>
```scss
.element {
  @include aspect-ratio("16/9");
}
```
```html
<iframe class="element" width="560" height="315" src="https://www.youtube.com/embed/JBc6JiRlsOU" title="YouTube video player" allow="accelerometer; autoplay; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe>
```
</Example>

## Images and embeds with a height attribute

Writing `width` and `height` on an `<img>` is the usual advice against layout
shift, and embed codes write them on their `<iframe>`. A `height` attribute is a
definite height, though, and with `width: 100%` also definite the browser
ignores `aspect-ratio`. Measured in Chrome 152, Firefox 156 and Safari 26.6.2 in
a 300px box, before 4.0.0:

| Element | Before 4.0.0 | Since 4.0.0 |
|---|---|---|
| `<img width="1600" height="900">`, ratio 4:3 | 300 × 900 | 300 × 225 |
| the same image inside `<picture>`, a flex item or a grid item | 300 × 900 | 300 × 225 |
| `<iframe width="560" height="315">`, ratio 16:9 | 300 × 315 | 300 × 169 |
| `<video width="640" height="480">`, ratio 16:9 | 300 × 480 | 300 × 169 |

Since 4.0.0 the mixin writes `height: auto` in a rule of its own, inside
`:where()`:

```css
:where(.element) { height: auto; }
```

A `height` attribute counts for less than any rule, so this one overrides it.
But `:where()` has no specificity, so a `height` your stylesheet sets, before
the include, after it, or through an element selector, still wins: a `<div>`
with `height: 400px` stayed 400px tall in all three browsers. A plain
`height: auto` in the mixin's own rule would have shrunk it to 225px.

<Example
  title="An image with its dimensions in the markup"
  caption="The width and height attributes stay, so the browser reserves the space before the file arrives, and the ratio still holds."
  listing="<img class=&quot;element&quot; src=&quot;/images/landscape.webp&quot; width=&quot;1400&quot; height=&quot;933&quot; alt=&quot;A wide landscape at first light&quot;>"
>
```scss
.element {
  @include aspect-ratio("4:3");
}
```
```html
<img class="element" src="/images/landscape.webp" width="1400" height="933" alt="A 4 by 3 box holding a cropped photograph" />
```
</Example>

<Example
  title="The ratio on its own"
  caption="If you want the ratio without the rest of the mixin, validateRatio accepts the same values and returns just the ratio."
>
```scss
.element {
  aspect-ratio: validateRatio("16:9");
}
```
</Example>

## Coming from Ratio Box or Responsive Video

Both of those mixins held a ratio with a `padding-top` hack, a pseudo-element
and an absolutely positioned child. The CSS `aspect-ratio` property made all of
that unnecessary, and it left the two mixins identical to each other, so they
were replaced by this single one.

The rename itself is mechanical. What is not mechanical is **where the mixin
goes**: the old mixins were applied to a wrapping element, and this one goes on
the element itself.

```scss
// Before, on a wrapper
.hero  { @include ratio-box("16/9"); }
.video { @include responsive-video("16/9"); }

// After, on the element
.hero  { @include aspect-ratio("16/9"); }
.video iframe { @include aspect-ratio("16/9"); }
```

<Hint kind="warning">

**This part is easy to get wrong.** A ratio on a **wrapper** does not size an
`<iframe>` inside it: the iframe keeps its intrinsic 300 by 150. Measured in a
browser at a container width of 640px, a ratio on the wrapper gives a 640 by 360
wrapper with a 304 by 154 iframe inside it, while a ratio on the iframe itself
gives 640 by 360 with no wrapper needed.

</Hint>

If you have a wrapper `<div>` around a video embed only to hold its ratio,
remove the wrapper along with the old mixin.
