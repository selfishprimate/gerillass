# Columnizer

<Member name="columnizer">

The **Columnizer** Sass mixin helps you **create evenly divided hypothetical columns** inside a container element, as many as the value you pass for the `$columns` argument. This lets you show all the children of the parent element as if they were lined up in columns. 

**Important:** The Columnizer mixin **must be applied to the parent** element to **align the children** inside it!
<Hint kind="info">

**Tip:** This mixin is very useful when you want to create **card-based design layouts**.

</Hint>

</Member>

## Arguments

<Arguments of="columnizer">
  <Argument name="$columns" type="number">Sets the number of the hypothetical columns. A number without a unit, or <code>var()</code>, <code>env()</code> or <code>attr()</code>.</Argument>
  <Argument name="$gutter" type="number (with unit)">Sets the space between the columns and between the rows, written as the container's <code>gap</code>. A length, <code>var()</code> or a maths function. Not a percentage and not below zero; see below. <code>0</code> is written as <code>0px</code>, because the gutter is multiplied inside <code>calc()</code>.</Argument>
  <Argument name="$fill" type="boolean">Lets the orphans fill the remaining gap at the end of the list. This argument is optional and <strong>should always come last</strong>. The default value is <code>false</code>.</Argument>
</Arguments>

<Hint kind="info">

**The gutter is a `gap` since 4.0.0.** Until then it was a right margin on the columns, taken off every nth column again, and a bottom margin on all of them. Measured in Chrome 152, Firefox 156 and Safari 26.6.2 on 432 calls, from one to six columns, with every kind of gutter, fractional container widths and right to left, the `gap` version lined every row up with both edges in all of them. The margins put the gutter on the wrong side in a right-to-left page, left a gutter under the last row, pushed a column onto the next row when the container also had a `gap`, and misaligned every row after a hidden column, since `:nth-child` still counts it. A count from a custom property with a gutter, `columnizer(var(--cols), 20px)`, did not compile at all.

</Hint>

<Hint kind="warning">

**Two things to know when moving to 4.0.0.**

- A margin you put on the columns now **adds** to the gap. The old margins used to override it.
- A `gap` written after the include replaces the gutter the column widths were computed with, so rows no longer end flush. Pass the gutter to the mixin.

</Hint>

<Hint kind="info">

**Everything inside the columns is `border-box`, and your own `box-sizing` wins.** The rule is written inside `:where()`, which has no specificity, so an input with `width: 100%` and padding fits its column on a page with no border-box reset, and a `box-sizing` you set anywhere, even `input { box-sizing: content-box }`, is kept. Until 4.0.0 the rule was `.grid *`, which overrode both of those. Measured in Chrome 152, Firefox 156 and Safari 26.6.2.

</Hint>

<Hint kind="info">

**A long word or a wide image keeps its column.** The columns carry `min-inline-size: 0`. Without it a flex item is at least as wide as its content, so one long word or a 400px image widened its column and pushed the row out of shape, in Chrome even for an image with `max-width: 100%`. Content that cannot fit now overflows its column instead, which `overflow-wrap: anywhere` on text or `max-width: 100%` on an image handles.

</Hint>

## What it refuses

A column count or gutter the browser drops stops the build. Measured in Chrome 152, `calc(100% / 3px)` drops the column width, and so does a gutter that is unitless, a word, or a unit that is not a length. Until 2.3.1 these compiled. A gutter of `0` used to be one of them, `(3 - 1) * 0` being a number rather than a length, and is now written as `0px`.

```scss
.grid {
  @include columnizer(3px);
}
```
```text
Error: `3px` is not a valid column count for `columnizer`: a column count has no unit. A browser drops the column width.
```

Since 4.0.0 a percentage gutter stops the build too. A column gap in `%` is a share of the container's width, but a row gap in `%` is a share of its height, which a wrapping row does not have: measured in all three browsers, the rows touched. A negative gutter is refused because `gap` cannot be negative, and the browser dropped it. Until 4.0.0 both worked through the margins. Use a length, or `vw` for a gutter that follows the viewport.

```scss
.grid {
  @include columnizer(3, 5%);
}
```
```text
Error: `5%` is not a valid gutter for `columnizer`: a row gap in % is a share of the container's height, which a wrapping row does not have, so the rows would touch. Pass a length, such as `2rem` or `3vw`.
```
