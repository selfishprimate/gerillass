# Columnizer

<Member name="columnizer">

The **Columnizer** Sass mixin lays the children of an element out in **equal columns**, as many as `$columns` says, with an optional gutter written as the container's `gap`. There are no column elements: the children are the columns, and the last row can be told to fill the width it has left. 

**Important:** The Columnizer mixin **must be applied to the parent** element to **align the children** inside it!
<Hint kind="info">

**Tip:** This mixin is very useful when you want to create **card-based design layouts**.

</Hint>

</Member>

## Arguments

<Arguments of="columnizer">
  <Argument name="$columns" type="number">How many columns the children are laid out in. A number without a unit, or <code>var()</code>, <code>env()</code> or <code>attr()</code>.</Argument>
  <Argument name="$gutter" type="number (with unit)">Sets the space between the columns and between the rows, written as the container's <code>gap</code>. A length, <code>var()</code> or a maths function. Not a percentage and not below zero; see below. <code>0</code> is written as <code>0px</code>, because the gutter is multiplied inside <code>calc()</code>.</Argument>
  <Argument name="$fill" type="boolean">Lets the orphans fill the remaining gap at the end of the list. This argument is optional and <strong>should always come last</strong>. The default value is <code>false</code>.</Argument>
</Arguments>

<Hint kind="info">

**The gutter is a `gap` since 4.0.0.** It was a right margin on the columns before, with a reset on every nth one, which put the gutter on the wrong side in a right-to-left page, left one under the last row, and lost its alignment as soon as a column was hidden or the count came from a custom property.

</Hint>

<Hint kind="warning">

**Two things to know when moving to 4.0.0.**

- A margin you put on the columns now **adds** to the gap. The old margins used to override it.
- A `gap` written after the include replaces the gutter the column widths were computed with, so rows no longer end flush. Pass the gutter to the mixin.

</Hint>

<Hint kind="info">

**Everything inside the columns is `border-box`, and your own `box-sizing` wins.** The rule is written inside `:where()`, which has no specificity, so an input with `width: 100%` and padding fits its column on a page with no reset, and a `box-sizing` you set anywhere is kept.

</Hint>

<Hint kind="info">

**A long word or a wide image keeps its column.** The columns carry `min-inline-size: 0`, since a flex item is otherwise at least as wide as its content. Content that cannot fit overflows its column instead, which `overflow-wrap: anywhere` on text or `max-width: 100%` on an image handles.

</Hint>

## What it refuses

A column count or gutter the browser drops stops the build. Measured in Chrome 152, `calc(100% / 3px)` drops the column width, and so does a gutter that is unitless, a word, or a unit that is not a length. Until 2.3.1 these compiled. A gutter of `0` used to be one of them, `(3 - 1) * 0` being a number rather than a length, and is now written as `0px`. A fraction is not refused: `columnizer(2.5)` is the layout where the next card is half in view.

```scss
.grid {
  @include columnizer(3px);
}
```
```text
Error: `3px` is not a valid column count for `columnizer`: a column count has no unit, and a browser drops the column width.
```

Since 4.0.0 a percentage gutter stops the build too. A column gap in `%` is a share of the container's width, but a row gap in `%` is a share of its height, which a wrapping row does not have: measured in all three browsers, the rows touched. A negative gutter is refused because `gap` cannot be negative, and the browser dropped it. Until 4.0.0 both worked through the margins. Use a length, or `vw` for a gutter that follows the viewport.

```scss
.grid {
  @include columnizer(3, 5%);
}
```
```text
Error: `5%` is not a valid gutter for `columnizer`: a row gap in % is a share of the container's height, which a wrapping row does not have, so the rows would touch. Pass a length, such as `2rem` or `3vw`.
```

Since 4.0.0 a count of zero or less stops the build as well, and this one a
browser does not drop: it works the `calc()` out. Measured in Chrome 152,
Firefox 156 and Safari 26.6.2, `calc(100% / 0)` is an infinite percentage and
left every column 33554432px wide in Chrome and Safari and 17895684px in
Firefox, while `calc(100% / -3)` clamps to a `0%` basis, so the columns shrink
to their text and there is no grid left.

```scss
.grid {
  @include columnizer(0);
}
```
```text
Error: `0` is not a valid column count for `columnizer`: a row has to hold at least one column, and a browser works this calc() out rather than dropping it, so `0` left every column millions of pixels wide and a negative count left them no wider than their text.
```

`$fill` takes `true` or `false`, and since 4.0.0 nothing else. A gutter and a
fill are told apart by their type when only one of them is passed, so a third
argument that was not a boolean came out `false` and quietly gave the last row
no fill, which is the opposite of what `columnizer(3, 20px, 1)` was asking for.

```scss
.grid {
  @include columnizer(3, 20px, 1);
}
```
```text
Error: `1` is not a valid $fill for `columnizer`: it takes `true` or `false`, and anything else is read as `false`, so the last row would not fill. Pass `true` to stretch the last row, or leave the argument out.
```
