# Validate Breakpoint

<Member name="validateBreakpoint">

Resolves a breakpoint name to its width. Anything else that could be a size comes back as it is, because the function is also used in declarations, where a percentage or a CSS function is valid. `null` comes back as `null`, so a declaration built from it is left out.

</Member>

## Arguments

<Arguments of="validateBreakpoint">
  <Argument name="$value" type="string | number">Accepts a key from <code>$map-for-breakpoints</code>, a length, a percentage, or a CSS function such as <code>var()</code> or <code>min()</code>.</Argument>
</Arguments>

## Examples

<Example caption="A breakpoint name used as a length, which is the reason the function is public: the name is in one place and the container follows it.">
```scss
.container {
  max-width: validateBreakpoint("large");
  margin: 0 auto;
}
```
</Example>

<Example caption="Anything that could be a size comes back as it is, and without its quotes. A declaration takes a percentage and a CSS function where a media condition cannot, which is why this function is more permissive than [Breakpoint](/docs/breakpoint).">
```scss
.a { width: validateBreakpoint("600px"); }
.b { max-width: validateBreakpoint(none); }
.c { width: validateBreakpoint(min(100%, 40rem)); }
```
</Example>

## What it refuses

**A word that is not a key, and a list.** Until 2.3.1 a word came back unchanged and a list gave its first item, so a name missing from the map compiled into CSS that did nothing. The keys are case-sensitive, so a name in the wrong case reaches this message too.

```scss
.container {
  max-width: validateBreakpoint("huge");
}
```
```text
Error: `huge` is not a breakpoint. $map-for-breakpoints has xsmall, small, medium, large, xlarge, xxl; pass one of those, or a length such as `600px`.
```

**A number no width can be**, which until 4.0.0 compiled straight into the declaration. Chrome 152 and Firefox 156 drop `width: 10deg`, `width: 2s`, `width: 3fr` and a unitless `width: 600` alike. A unitless `0` is kept, because it is `$map-for-breakpoints`'s own `xsmall`.

```scss
.container {
  max-width: validateBreakpoint(600);
}
```
```text
Error: `600` is not a breakpoint: it is a number no width can be. A browser drops the declaration. Pass a length such as `600px`, a percentage, or a key from $map-for-breakpoints.
```

**A colour and a boolean**, which came back untouched and were dropped the same way, and **a map or an empty list**, which used to stop the build with Sass's own `() isn't a valid CSS value` from a value this function had just handed back. An empty string is refused too.

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** What it returns carries no quotes. A condition interpolates them away, so `breakpoint(min, "600px")` has always worked, but a declaration does not: `width: validateBreakpoint("600px")` used to write `width: "600px"`, which both engines drop. The queries every condition mixin writes are unchanged.

</Hint>
