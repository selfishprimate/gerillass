# Validate Breakpoint

<Member name="validateBreakpoint">

Resolves a breakpoint name to its width. Anything else that could be a size comes back as it is, because the function is also used in declarations, where a percentage or a CSS function is valid. `null` comes back as `null`, so a declaration built from it is left out.

</Member>

## Arguments

<Arguments of="validateBreakpoint">
  <Argument name="$value" type="string | number">Accepts a key from <code>$map-for-breakpoints</code>, a length, a percentage, or a CSS function such as <code>var()</code> or <code>min()</code>.</Argument>
</Arguments>

## Examples

<Example caption="A breakpoint name used as a length.">
```scss
.container {
  max-width: validateBreakpoint("large");
  margin: 0 auto;
}
```
</Example>

## What it refuses

A word that is not a key, and a list. Until 2.3.1 a word came back unchanged and a list gave its first item, so a name missing from the map, or spelt in another case, compiled into CSS that did nothing.

```scss
.container {
  max-width: validateBreakpoint("huge");
}
```
```text
Error: `huge` is not a breakpoint. $map-for-breakpoints has xsmall, small, medium, large, xlarge; pass one of those, or a length such as `600px`.
```
