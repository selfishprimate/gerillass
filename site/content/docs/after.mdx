# After

<Member name="after">

The **After** Sass mixin helps you generate content or a style element after the actual content of the selected element or elements.

</Member>

## Arguments

<Arguments of="after" footnote="To render the value of a data attribute, pass its name, which must start with `data-`. See the examples for more.">
  <Argument name="$content" type="string, function">You can pass content as a string, or the name of a data attribute such as <code>data-content</code> to render its value. A CSS function, <code>var()</code>, <code>attr()</code>, <code>counter()</code> or <code>counters()</code>, is written as it is rather than quoted into text. With no argument the mixin writes an empty <code>content</code> that anything else sets overrides; see below.</Argument>
</Arguments>

## Examples

<Example caption="A string is written straight into `content`. The markup is printed first: `/ month` is nowhere in it, which is the point of a pseudo-element." listing="<span class=&quot;price&quot;>$19</span>">
```scss
.price {
  @include after(" / month");
}
```
```html
<style>
  .price { font: 800 30px Inter, ui-sans-serif, system-ui, sans-serif; color: #2f3937; }
</style>
<span class="price">$19</span>
```
</Example>

<Example caption="A declaration block styles the pseudo-element instead, and it needs no text: with no argument the mixin writes `content: &quot;&quot;` for you, so a block of styles alone draws a shape. The dot is not in the markup either. Until 4.0.0 this drew nothing, because a pseudo-element with no `content` is not rendered." listing="<button class=&quot;bell&quot; aria-label=&quot;Notifications&quot;>&#128276;</button>">
```scss
.bell {
  @include after {
    position: absolute;
    top: 6px;
    right: 6px;
    width: 8px;
    height: 8px;
    border-radius: 50%;
    background: #ed6a5a;
  }
}
```
```html
<style>
  .bell {
    position: relative; display: inline-flex; align-items: center; justify-content: center;
    width: 40px; height: 40px; border: 1px solid #dee0cd; border-radius: 8px;
    background: #fff; font-size: 18px; color: #2f3937;
  }
</style>
<button class="bell" aria-label="Notifications">&#128276;</button>
```
</Example>

<Example caption="An argument that starts with `data-` is read from the markup rather than written as text, so every element carries its own." listing="<span class=&quot;price&quot; data-currency=&quot; TL&quot;>200</span>
<span class=&quot;price&quot; data-currency=&quot; €&quot;>18</span>">
```scss
.price {
  @include after("data-currency");
}
```
```html
<style>
  .price { font: 600 20px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #2f3937; }
  .price + .price { margin-left: 18px; }
</style>
<span class="price" data-currency=" TL">200</span>
<span class="price" data-currency=" €">18</span>
```
</Example>

<Example caption="The two forms together: the attribute for the text, and a block for how it looks." listing="<span class=&quot;metric&quot; data-unit=&quot;ms&quot;>184</span>
<span class=&quot;metric&quot; data-unit=&quot;%&quot;>99.9</span>">
```scss
.metric {
  @include after("data-unit") {
    margin-left: 2px;
    font-size: 0.55em;
    font-weight: 500;
    color: #657167;
  };
}
```
```html
<style>
  .metric { font: 700 28px/1.3 Inter, ui-sans-serif, system-ui, sans-serif; color: #2f3937; }
  .metric + .metric { margin-left: 22px; }
</style>
<span class="metric" data-unit="ms">184</span>
<span class="metric" data-unit="%">99.9</span>
```
</Example>

<Hint kind="warning">

**What the default overrides, and what it does not.** Measured in Chrome 152, Firefox 156 and Safari 26.6.2: the default is written as `:where(.bell)::after`, which has only the pseudo-element's specificity, so a `content` in the block, or in any rule for the element with a class or an element selector, before or after the include, still wins. Three things lose to it. A `content` that only comes from another state, such as `:hover` or a media query, leaves the empty box drawn the rest of the time, so write `content: none` in the block and let the state put it back. On a `q` element it replaces the browser's quotation marks; write `content: close-quote` in the block to keep them. And a bare `::after { content: ... }` rule written before the include loses, since both have the same specificity.

</Hint>
