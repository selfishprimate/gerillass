# After

<Member name="after">

The **After** Sass mixin helps you generate content or a style element after the actual content of the selected element or elements.

</Member>

## Arguments

<Arguments of="after" footnote="To render the value of a data attribute, pass its name, which must start with `data-`. See the examples for more.">
  <Argument name="$content" type="string, function">You can pass content as a string, or the name of a data attribute such as <code>data-content</code> to render its value. A CSS function, <code>var()</code>, <code>attr()</code>, <code>counter()</code> or <code>counters()</code>, is written as it is rather than quoted into text. With no argument the mixin writes an empty <code>content</code> that anything else sets overrides; see below.</Argument>
</Arguments>

## Examples

<Example caption="A string argument is written straight into `content`, which is the shortest form there is.">
```scss
.price {
  @include after(" / month");
}
```
```html
<style>
  body { background: #f8fafc; font: 15px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #0f172a; }
  .card { width: 230px; padding: 20px; border-radius: 16px; background: #fff; box-shadow: 0 6px 20px rgb(15 23 42 / 0.08); }
  .card b { display: block; margin-bottom: 6px; font-size: 13px; letter-spacing: 0.08em; text-transform: uppercase; color: #64748b; }
  .price { font: 800 30px Inter, ui-sans-serif, system-ui, sans-serif; letter-spacing: -0.02em; }
  .price::after { font: 600 14px Inter, ui-sans-serif, system-ui, sans-serif; color: #64748b; }
</style>
<div class="card"><b>Team</b><span class="price">$19</span></div>
```
</Example>

<Example caption="A declaration block styles the pseudo-element, so the tag beside the heading is one rule rather than a second element in the markup.">
```scss
.feature {
  @include after {
    content: " Beta";
    padding: 2px 8px;
    margin-left: 8px;
    border-radius: 999px;
    background: #fef08a;
    color: #854d0e;
    font-size: 11px;
    font-weight: 700;
  }
}
```
```html
<style>
  body { background: #f8fafc; font: 15px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #0f172a; }
  .feature { display: inline-flex; align-items: center; font-weight: 700; font-size: 17px; }
</style>
<span class="feature">Container queries</span>
```
</Example>

<Example caption="A `data-` attribute name is read from the markup instead of a string, so each element carries its own text." listing="<div class=&quot;element&quot; data-currency=&quot; TL&quot;>200</div>">
```scss
.element{
  @include after("data-currency");
}
```
```html
<style>
  .element { font: 600 20px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
</style>
<div class="element" data-currency=" TL">200</div>
```
</Example>

<Example caption="The two forms together: the attribute for the text, and a block for how it looks." listing="<div class=&quot;element&quot; data-currency=&quot;TL&quot;>200</div>">
```scss
.element{
  @include after("data-currency"){
    margin-left: 4px;
    font-size: .6em;
    color: red;
  };
}
```
```html
<style>
  .element { font: 600 20px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
</style>
<div class="element" data-currency="TL">200</div>
```
</Example>

## Interface examples

<Example caption="An arrow after every link that opens in a new tab, so a reader knows before clicking. The selector picks the links; the mixin writes the arrow.">
```scss
a[target="_blank"] {
  @include after(" ↗") {
    font-size: 0.85em;
  }
}
```
```html
<style>
  p { font: 15px/1.6 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
  a { color: #2563eb; }
</style>
<p>Read the <a href="#">installation guide</a> first, then the <a href="#" target="_blank">release notes on GitHub</a>.</p>
```
</Example>

<Example caption="A required-field marker. The asterisk is decoration, and the input itself says `required`, which is what a screen reader announces.">
```scss
.label-required {
  @include after(" *") {
    color: #dc2626;
  }
}
```
```html
<style>
  form { display: grid; gap: 12px; max-width: 280px; font: 14px/1.4 Inter, ui-sans-serif, system-ui, sans-serif; color: #18181b; }
  label { display: grid; gap: 6px; font-weight: 500; }
  input { height: 34px; padding: 0 10px; border: 1px solid #e4e4e7; border-radius: 6px; font: inherit; }
</style>
<form onsubmit="return false">
  <label><span class="label-required">Email</span><input type="email" required></label>
  <label><span>Company</span><input></label>
</form>
```
</Example>

<Example caption="Separators in a breadcrumb trail, after every item but the last, with the **Except** mixin choosing the items. They live in CSS, so the markup stays a plain list.">
```scss
.crumb {
  @include except(last) {
    @include after("/") {
      margin: 0 8px;
      color: #a1a1aa;
    }
  }
}
```
```html
<style>
  .crumbs { display: flex; list-style: none; margin: 0; padding: 0; font: 14px/1 Inter, ui-sans-serif, system-ui, sans-serif; }
  .crumb a { color: #52525b; text-decoration: none; }
  .crumb:last-child { color: #18181b; font-weight: 500; }
</style>
<ol class="crumbs">
  <li class="crumb"><a href="#">Home</a></li>
  <li class="crumb"><a href="#">Docs</a></li>
  <li class="crumb">After</li>
</ol>
```
</Example>

## Drawing with no content

<Example caption="A notification dot on a bell icon. With no argument the mixin writes `content: &quot;&quot;` for you, so a block of styles alone draws the dot. Until 4.0.0 this drew nothing, because a pseudo-element with no `content` is not rendered.">
```scss
.bell {
  @include after {
    position: absolute;
    top: 6px;
    right: 6px;
    width: 8px;
    height: 8px;
    border-radius: 50%;
    background: #ef4444;
  }
}
```
```html
<style>
  .bell {
    position: relative; display: inline-flex; align-items: center; justify-content: center;
    width: 40px; height: 40px; border: 1px solid #e4e4e7; border-radius: 8px;
    background: #fff; font-size: 18px; color: #18181b;
  }
</style>
<button class="bell" aria-label="Notifications">&#128276;</button>
```
</Example>

<Example caption="A tooltip whose text appears on hover. The `content` comes from the hover rule only, so the block says `content: none`: without it the default would draw the empty tooltip box all the time. **Hover over the button in the result.**" listing="<button class=&quot;tip&quot; data-tip=&quot;Copied to clipboard&quot;>Copy link</button>">
```scss
.tip {
  @include after {
    content: none;
    position: absolute;
    bottom: calc(100% + 6px);
    left: 50%;
    translate: -50% 0;
    padding: 4px 8px;
    border-radius: 4px;
    background: #18181b;
    color: #fafafa;
    font-size: 12px;
    white-space: nowrap;
  }
  &:hover::after {
    content: attr(data-tip);
  }
}
```
```html
<style>
  .row { padding-top: 36px; font: 14px/1 Inter, ui-sans-serif, system-ui, sans-serif; }
  .tip {
    position: relative; height: 36px; padding: 0 14px; border: 1px solid #e4e4e7;
    border-radius: 6px; background: #fff; color: #18181b; font: inherit; cursor: pointer;
  }
</style>
<div class="row"><button class="tip" data-tip="Copied to clipboard">Copy link</button></div>
```
</Example>

<Hint kind="warning">

**What the default overrides, and what it does not.** Measured in Chrome 152, Firefox 156 and Safari 26.6.2: the default is written as `:where(.bell)::after`, which has only the pseudo-element's specificity, so a `content` in the block, or in any rule for the element with a class or an element selector, before or after the include, still wins. Three things lose to it. A `content` that only comes from another state, such as `:hover` or a media query, leaves the empty box drawn the rest of the time, so write `content: none` in the block, as above. On a `q` element it replaces the browser's quotation marks; write `content: close-quote` in the block to keep them. And a bare `::after { content: ... }` rule written before the include loses, since both have the same specificity.

</Hint>
