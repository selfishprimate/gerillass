# Reset Figure
<Member name="reset-figure">

The **Reset Figure Sass mixin** helps you reset the margin values of `<figure>` elements to `0` and make the `<img>` element inside them responsive (fluid). It does this by setting the width CSS property of the `<img>` element to `100%`.

</Member>

## Examples

<Example caption="Called on a `<figure>`, it takes off the margin a browser gives one, so the picture sits where the layout puts it.">
```scss
figure{
  @include reset-figure;
}
```
```html
<figure>
  <img src="/images/backgrounds/06.jpg" alt="A photograph" style="width: 100%" />
  <figcaption style="font-size: 14px; opacity: 0.7">A figure with no margin of its own.</figcaption>
</figure>
```
</Example>

<Hint kind="warning">

**Changed in Gerillass 4.0.0.** The image inside the figure is styled by [responsive image](/docs/responsive-image), which no longer upscales a small image and now keeps its proportions against a `height` attribute. That page has the measurements.

</Hint>

<Hint kind="warning">

**The image rule is inside `:where()` since 4.0.0, so your own rule wins.** It used to compile to `figure img`, and measured in Chrome 152, Firefox 156 and Safari 26.6.2 that beat a page's own `img { display: inline; max-inline-size: none }` in all three, so one figure's image could not be opted out without reaching for a class. The figure itself keeps the specificity of the selector you called the mixin in, which is what the call asked for; only the image is lowered. This is the shape [Border Box](/docs/border-box) and [Columnizer](/docs/columnizer) settled on.

</Hint>

## What it refuses

The mixin writes declarations, so it needs a rule to write them into.

```scss
@include reset-figure;
```
```text
Error: `reset-figure` writes its declarations into the rule it is called in, so call it inside a selector, such as `figure { @include reset-figure; }`.
```
