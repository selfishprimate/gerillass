# Center

<Member name="center">

The **Center** Sass mixin puts an absolutely positioned element in the middle
of its parent, on either axis or both, with the half-its-own-size offset that
makes it work for an element whose size you do not know.

Two things have to be true for it, and the mixin cannot write either: the
element is `position: absolute` or `fixed`, and its parent is positioned too.

</Member>

## Arguments

<Arguments of="center" footnote="Pass the `both` value to center an element on both the horizontal and vertical axes, or pass nothing at all.">
  <Argument name="$axis" type="string">Sets the axis of the alignment. Accepts the values <code>horizontal</code>, <code>vertical</code>, and <code>both</code>. The default value is <code>both</code>.</Argument>
</Arguments>

## Examples

<Example caption="With no argument the element is centred on both axes, which is where a play button goes.">
```scss
.parent-element {
  position: relative;
  .element {
    position: absolute;
    @include center;
  }
}
```

<Example caption="**A `transform` of the element's own composes with the centring rather than replacing it.** Hover either card: one scales, the other rotates, and both stay in the middle. Until 4.0.0 the offset was written into `transform`, so a rule like these replaced it and the card jumped down and to the right by half its own size.">
```scss
.parent-element {
  position: relative;

  .element {
    position: absolute;
    @include center;
    transition: transform .2s;
  }

  .element--zoom:hover {
    transform: scale(1.15);
  }

  .element--tilt:hover {
    transform: rotate(-6deg);
  }
}
```
```html
<style>
  body { margin: 0; padding: 0; background: #fafaf8; font: 14px/1.5 Inter, ui-sans-serif, system-ui, sans-serif; color: #657167; }
  .row { display: grid; grid-template-columns: 1fr 1fr; gap: 12px; padding: 12px; }
  .parent-element { height: 180px; overflow: hidden; border-radius: 18px; background: linear-gradient(140deg, #2f3937, #668f80); }
  .element { margin: 0; padding: 14px 20px; border-radius: 14px; background: #fafaf8; color: #2f3937; font: 700 15px Inter, ui-sans-serif, system-ui, sans-serif; white-space: nowrap; cursor: pointer; }
</style>
<div class="row">
  <div class="parent-element"><h2 class="element element--zoom">Hover to scale</h2></div>
  <div class="parent-element"><h2 class="element element--tilt">Hover to rotate</h2></div>
</div>
```
</Example>

<Hint kind="info">

**`translate` is the one property still the mixin's.** `transform`, `rotate` and `scale` compose with the centring, but a rule of your own that sets `translate` replaces the offset and the element jumps by half its own size. Nothing in CSS moves an element by half its own size except a transform, so there is no way round it from inside the mixin.

**If you control the parent, you may not need the mixin.** Make it `display: grid` and give the absolutely positioned child `place-self: center`: it centres an element of any size, writes no transform at all, and leaves `translate` free for an animation. The catch is the one the mixin cannot take on for you — turning the parent into a grid changes the layout of everything else inside it.

```scss
.parent-element {
  display: grid;

  .element {
    position: absolute;
    place-self: center;
  }
}
```

Two things that look like alternatives and are not, both measured in Chrome 152, Firefox 156 and Safari 26.6.2: `inset: 0; margin: auto` stretches an element with no size of its own to fill the parent instead of centring it, and anchor positioning's `position-area: center` centres an element on a *sibling* anchor but not on its own containing block, so it does not answer this at all.

</Hint>

## What it refuses

The axis is one of three words, and anything else stops the build rather than
writing an offset for an axis that does not exist.

```scss
.element {
  @include center(diagonal);
}
```
```text
Error: `diagonal` is not a valid $axis for `center`. Pass one of: both, horizontal, vertical.
```
